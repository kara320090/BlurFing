# 손가락별 둥근 손끝 후처리

2026-10-16. 사용자가 요청한 별도 검은 가림 경로이며 기존 V6 가중치, COLFISPOOF, frozen 보호 변환 수학, pitch/feature 판정값을 변경하지 않는다. 원본 사진·정답·모델·진단 이미지는 비공개 위치에 보존한다.

후속 [실제 지문 보호 변환 연결과 검증](PHOTO_ROUNDED_NATIVE_20261016.md)은 별도 실행기 `BlurFing-Rounded-Protect.cmd`를 사용한다. 이 문서의 실행기는 검출 영역의 검정 가림 미리보기다.

## 원인과 처리

보고된 전체 손 사진의 coarse 후보는 손가락 아래쪽과 손바닥 일부까지 이어진다. 실제 semantic BODY는 손가락들을 손바닥으로 연결하고, class-2 marker는 일부 손끝에서 누락되거나 조각난다. 기존 watershed owner 하나가 여러 손가락과 아래쪽 피부를 포함해 기준 폭과 중심축이 과대 추정됐다. 해당 owner의 작업 좌표 reference width는 약 144.35px였고 인접 정상 손가락 owner는 약 33.09px였다. 이 상태의 넓은 후보를 EdgeTAM dense prompt로 주면 잘못된 후보까지 충실히 채운다. 단순 closing/convex hull을 전체 합집합에 적용하면 이러한 연결을 악화시킬 수 있다.

`photo_rounded_pad_v1.py`는 먼저 손가락 owner를 구분한다. 검증된 MediaPipe worker 결과가 있으면 기존 native 좌표 TIP–DIP/IP 방향과 관절 위치를 사용한다. 축의 1/4·1/2·3/4 위치에서 축을 포함하는 연속 단면의 폭을 측정하고 중앙값을 취한다. 관절 쪽은 직선으로 자르고 손끝은 반원 형태로 구성하며 관측 BODY 밖을 가리지 않는다. 원래 V6 마스크와 다시 교집합하지 않으므로 V6의 열린 빈틈이 재발하지 않는다. 새로운 프롬프트·학습·threshold sweep은 없다.

관절을 검출하지 못하면 기존 후보의 **국소 축**으로 추정 영역을 만든다. 손바닥을 포함한 전체 owner의 주축을 그대로 쓰지 않는다. 관절이 관측되지 않은 상태에서는 기존 보호 픽셀을 삭제하지 않고 보완만 한다. 유효한 단면·방향·끝 경계를 얻지 못한 owner는 기존 가림을 유지하고 거절 이유를 보고한다. 이것은 실제 관절 또는 완전한 지문 영역을 확정하는 방법이 아니다.

첫 실험에서 관절 미검출 사진까지 고정 폭으로 교체하면 기존 보호 영역이 크게 줄어드는 것을 확인했다(개발 GT13 합산 recall 0.664472). 해당 방식은 실행기에 채택하지 않았다. 국소 축과 기존 보호 픽셀 보존 계약으로 수정한 두 번째 결과를 사용한다. 두 실험과 원본 출력은 각각 비공개 경로에 보존했다. 개발 결과를 보고 수정한 반복 실험이며 독립 one-shot 검증이 아니다.

## 검증과 한계

기존 21장과 보고된 세 손가락 사진, 총 22장을 캐시된 semantic/V6/pose 출력으로 재평가했다. 정답이 있는 13장은 학습에 사용된 개발 자료다. GT는 후처리 입력이나 사례별 정책 선택에 사용하지 않았다.

| 방법 | GT13 합산 IoU | GT 화소 recall | 과잉 화소 |
|---|---:|---:|---:|
| 넓은 coarse 후보 | 0.562837 | 0.696218 | 904,738 |
| EdgeTAM dense/coarse 제한 + 기존 가림 | 0.729047 | 0.913813 | 967,564 |
| 기존 V6 + Coverage 보완 | 0.869647 | 0.909894 | 176,684 |
| 새 둥근 손끝 후처리 | 0.869346 | 0.909601 | 176,784 |

전체 손 보고 사진은 5개 둥근 손끝으로 분리돼 아래쪽 넓은 연결이 사라졌다. 이 사진에서 과잉 화소는 EdgeTAM dense 합집합의 795,714에서 69,917로 감소했고 IoU는 0.409902에서 0.841722로 증가했다. 다만 기존 V6 Coverage의 IoU 0.842442보다 개선됐다고 볼 수 없고, recall도 0.952996에서 0.939714로 소폭 감소했다. 모양을 규칙화하는 과정에서 실제 지문 가장자리를 제외할 수 있다는 한계다.

세 손가락 사례는 3개 연속적인 손끝 cap을 적용했다. 사람 정답이 없어 후보와의 일치도를 실제 검출률로 보고하지 않는다. 관절 미검출 시 기존 가림을 보존하므로 작은 불필요한 조각도 남을 수 있다. BODY 자체가 누락한 피부는 새 원으로 무조건 채우지 않는다. 손등/손톱과 지문 면을 완전히 구분하거나 지문 식별 저항성을 검증한 결과가 아니다.

따라서 **새 명시적 실행 옵션**으로 제공하며 기존 기본 실행기를 일괄 교체하지 않는다. 새 Linux/Android 동등성 또는 새로운 촬영 그룹의 정답 성능은 아직 검증하지 않았다.

관련 테스트 **38개**가 통과했다. 단면 주변의 떨어진 조각·한 단면의 옆 가지, 90도 회전·반전, NaN/잘못된 좌표·크기/메모리 거절, 관절 미검출 시 기존 보호 영역 보존, owner 분리, 실제 PNG 저장/EXIF/ICC 계약을 포함한다. 두 보고 사례를 새 `.cmd` 실행기로 COLFISPOOF/V6/MediaPipe부터 다시 실행해 5개/3개 cap 적용을 확인했다. 캐시 기반 비교 결과와 최종 마스크가 정확히 일치하고, 후처리 전 마스크도 기존 실행 결과와 일치했다. 저장 RGB는 실제 마스크 안에서 0이고 밖에서는 원본과 동일했으며 EXIF/ICC가 보존됐다. 기존 비공개 원본/GT/semantic 자료 138개와 V6 모델 해시도 보존됐다.

## 사용

CLI `protect_photo_pitch_free_v1.py`의 `--rounded-pads`를 선택한다. 관절 기반 처리를 위해 `--include-observed-pose`를 함께 사용한다. 스캐너 입력은 기존 scanner ROI 경로로 분기한다. 기존 후보/실제 적용 마스크·최종 RGB 외에 `before_rounding_mask.png`, `rounded_pad_metadata`를 기록한다. 후보 적용률이 낮아도 넓은 잘못된 후보를 제거한 결과일 수 있으므로 보호 성공률로 해석하지 않는다.

로컬 사용자 실행기는 `outputs/BlurFing-Rounded-Pad-Test.cmd`다. 결과는 `outputs/pitch-free-tests/<실행별 폴더>/protected.png` 및 `comparison.png`에 저장한다. 새 비교 페이지는 `outputs/rounded-pads-v2-20261016/comparison.html`이다.
