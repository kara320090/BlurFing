# V32 실험적 사진 고속 경로

15초대 초반을 목표로 처리 구조를 변경했다. 이 목표의 충족 여부는 실제 HTTP 요청부터 응답 검증·PNG 저장/재읽기까지 측정한다. 모델 준비 시간은 별도로 기록한다. 개별 연산 시간이나 저장된 결과의 표시 시간을 전체 처리 시간으로 사용하지 않는다.

## 설정과 처리 방식

비공개 실행 설정의 `photo`에 다음을 지정하고 서버를 재시작한다.

```json
{"resident_worker": true, "hand_roi": true, "analysis_profile": "fast_v32"}
```

`native`가 기본값이며 기존 V6 타일 검출·주름 탐색·V23 경계 보정 경로를 유지한다. V6 모델은 서버 시작 시 기존 자산 계약에 따라 준비하지만 **fast_v32 요청에서는 V6 추론을 사용하지 않는다.**

고속 모드는 실제 COLFISPOOF DeepLab의 BODY/TIP와 실제 MediaPipe 관측을 함께 사용한다. semantic TIP가 손끝 관측 위치에 있고 손끝·중간점이 BODY 안에 있는 손가락만 선택한다. V6 마스크를 대신 만들거나 미관측 손가락을 사각형으로 승인하지 않는다. 미관측은 미적용으로 남고 V6로 몰래 재시도하지 않는다.

DeepLab 내부 입력 확대를 4608에서 1536으로 바꾸며 외부 가중치 파일은 수정하지 않는다. 손 전체 ROI, RGB 경계 보정과 원본 좌표의 cap 검증을 유지한다. 고속 모드의 근위 경계는 관측 IP/DIP 관절이며 별도의 사진 주름 탐색으로 측정한 경계가 아니다. V27 생성 재질에 V21/V22 외관 보정을 적용하고 V23 junction fit은 생략한다. 이 차이로 후보·경계·생성 RGB가 기존 모드와 달라질 수 있으며 픽셀 동등성을 주장하지 않는다.

전체 사진과 손 ROI는 축소하지 않는다. 최종 PNG는 요청과 같은 해상도이며 적용 밖과 거절 영역의 원본 RGB를 보존한다. 손가락별 후보는 분리된 조각도 하나의 원자적 그룹으로 묶고, 어느 조각이든 승인되지 않으면 그 그룹 전체를 거절한다. 소유가 정해지지 않은 후보 픽셀은 별도 미검토 그룹으로 모두 유지한다. 개수는 실제 손가락 개수·보호 성공률이 아니다.

## 공통 최적화와 검증 범위

MediaPipe 입력을 줄인 시험에서도 접힌 엄지 주변 적용이 달라져 채택하지 않았다. 손 관측은 원본 격자의 입력을 사용한다. 서버 준비 시 실제 손 모델을 합성 검정 영상으로 워밍업한다. 사진·결과를 미리 저장해 재생하지 않는다. 고속 cap에는 관측 끝마디 길이와 폭의 일관성 검사를 추가하지만 이 공학적 검사도 해부학적 정답이나 전체 보호의 증거는 아니다.

- V27 재질과 각 외관 보정 단계의 독립 영역을 최대 두 작업으로 처리한다. 단계 순서는 유지하고, 전체 RGB 사본 예산이 64MiB를 넘으면 직렬 처리한다. 합성 fixture에서 직렬·병렬 RGB와 메타데이터를 비교한다.
- 같은 요청의 동일 BODY/TIP 하위 문제만 내용 해시로 재사용한다. 배열은 복사하고 요청 종료·예외에서 모두 폐기한다. 사진 처리 결과를 요청 간 재사용하지 않는다.
- 소스 파일 전체 검사는 독점 요청의 시작과 종료에 수행한다. 중간 단계 검사는 그 최종 봉인까지 유예하며 **봉인 성공 전에 응답을 공개하지 않는다.** 소스 추가·삭제·변경 시 결과를 내보내지 않는다. 단독 실행의 즉시 검사와 외부 자산·입력 검증은 유지한다.
- PNG의 CRC·제한된 zlib 스트림·해상도·RGB8/L8·EXIF·비정상 메타데이터 검사를 유지하면서 OpenCV 디코딩을 사용한다. OpenCV가 없으면 기존 Pillow 경로를 쓴다. 채널 순서나 방향은 바꾸지 않는다.
- 큰 RGB PNG는 Sub 필터와 최대 4개 병렬 deflate 블록으로 압축한다. 중간 블록을 FULL_FLUSH로 끝내고 마지막만 FINISH로 끝내어 헤더·Adler 체크섬이 하나인 표준 zlib 스트림을 만든다. 이는 무손실이며 EXIF 처리와 15MiB 초과 시 원래 인코더로 재시도하는 동작을 유지한다. 서로 다른 행 경계·작업 수에서 엄격한 PNG 검증과 픽셀 동등성을 검사한다.

입력 ROI를 별도로 축소한 실험은 처리 범위가 손바닥까지 번져 채택하지 않았다. 고속 모드도 전체 지문 검출·해부학적 경계·생체 보호 효과를 보장하지 않는다. 기존 미검출·거절 경고와 실제 적용/거절 마스크를 유지한다. 현재 검증은 Windows 개발 장비이며 학교 Ubuntu와 실물 Android의 검증을 대신하지 않는다.

## 실제 HTTP 측정

2026-10-21, Windows i9-13980HX·RTX 4060 Laptop GPU, 3000×4000 PNG, 준비된 서버에 순차 loopback 요청을 보냈다. DeepLab은 실제 CUDA 실행이며 사진·관측·생성 결과를 요청 간 재사용하지 않았다. 모델 시작/준비 40.69초는 아래 시간에 포함되지 않는다.

| 개발 자료 | 서버 처리 | HTTP 응답 | 클라이언트 검증·PNG 저장/재읽기 포함 | 적용/거절 그룹 |
|---|---:|---:|---:|---:|
| 제공 사진 1회 | 17.156초 | 17.439초 | 19.738초 | 2 / 2 |
| 제공 사진 2회 | 16.516초 | 16.786초 | 19.238초 | 2 / 2 |
| 제공 사진 3회 | 16.016초 | 16.285초 | 18.570초 | 2 / 2 |
| 인수 사진 재실행 | 22.422초 | 22.589초 | 24.757초 | 2 / 1 |

**15초대 초반 목표는 미달이다.** 제공 사진의 이전 V31 HTTP·검증·저장/재읽기는 37.26초·37.76초였으나 처리 정책도 변경됐으므로 동일 픽셀의 속도 비교로 해석하지 않는다. 두 입력 모두 개발 자료이며 위 반복 횟수는 독립 정확도나 모든 사진의 시간 보장이 아니다. 네 요청에서 원본 해상도와 적용 밖 원본 RGB의 정확한 보존을 확인했다. 미적용·미검출이 남을 수 있다.

같은 제공 사진의 PNG 인코딩만 별도로 측정하면 OpenCV 압축 레벨 1은 1.232초/13,422,817바이트, 병렬 무손실 인코더는 0.304초/13,649,182바이트였다. 두 PNG를 다시 읽은 RGB는 정확히 같았다. 이 인코딩 시간은 전체 요청 시간이 아니다.

새 `native` 경로의 고정 시드 실제 실행 한 번을 변경 전 V31 기준 출력과 비교하여 최종 RGB·적용 마스크·후보 마스크의 차이가 0임을 확인했다. 이 제어 실행은 다른 검사와 동시 실행했으므로 시간을 성능 자료로 재사용하지 않는다.

공개 회귀는 pytest 278개, 추가 소스·내보내기·모델 unittest 51개가 통과했다. JDK 21에서 Android PNG codec 단위 검사 8개도 통과했으며, 병렬 deflate 합성 PNG와 비공개 12MP 실제 반환 PNG의 픽셀 해시를 교차 확인했다. 설치된 JDK 25에서의 Gradle 호환 실패 후 기존 휴대용 JDK 21로 재실행했으며 시스템 설정은 수정하지 않았다. 합성 자료 검사와 위 실제 모델 실행은 별도 증빙이다. 실제 센서·실물 Android·학교 Ubuntu의 완료로 표시하지 않는다.
