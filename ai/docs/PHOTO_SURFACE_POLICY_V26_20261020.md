# 지문선 관측과 손끝 영역 합성의 분리

2026-10-20 사용자가 흐린 손끝도 처리하도록 정책 변경을 요청했다. 자동 `synthetic_v23`의 기본 선택 정책은 `surface_v26`이며 렌더러·가중치·API 엔진명은 유지한다. 이전 `strict_ridge_v23`은 CLI로 명시해 재현할 수 있다.

## 달라진 선택 규칙

이전 자동 정책은 손끝 경계를 계산했어도 원본 지문선 반복 증거를 찾지 못하면 원본을 반환했다. 새 정책은 다음을 분리한다.

1. **원본 지문선 관측:** 기존 관측기를 그대로 실행한다. 결과가 불확실하면 계속 `observed=false`이며 지문 부재·존재·복원 성공으로 바꾸지 않는다.
2. **손끝 영역 선택:** 해시로 결합된 원본 V6/semantic TIP 근거와 관측 자세가 지지하는 손가락의 영역 안에서, 경계 계산을 통과한 후보 전체에만 예방적 합성을 허용한다. 일반 추정기의 후보·미선택 손가락·표시 사각형만으로는 이 권한을 얻지 않는다.
3. **실제 합성 승인:** 기존 렌더러의 생성 질감 검사와 적용 밖 원본 보존을 통과해야 한다. 생성 실패를 성공으로 바꾸거나 처리 마스크를 임의로 늘리지 않는다.

경계 밖 화소, 미확인 후보, 렌더러 미해결 영역은 계속 원본을 유지한다. 경계 추정 자체에는 오탐·누락 가능성이 있으며 전체 사진 보호 효과가 검증된 것은 아니다. 흐린 원본의 실제 지문을 복원한 결과가 아니라 선택 영역에 생성한 합성 질감이다.

## 응답·Android 표시

지문선 확인 없이 합성된 영역은 일반 `TRANSFORMED`와 구분하여 `TRANSFORMED_PRECAUTIONARY_SURFACE`를 전달한다. 해당 영역이 실제 적용됐을 때만 `PRECAUTIONARY_SURFACE_WITHOUT_RIDGE_CONFIRMATION` 경고를 포함한다. 실패한 렌더링에는 이 성공 사유를 붙이지 않는다. 서버와 Android 모두 다른 엔진의 이 사유 및 경고 누락을 거절한다.

Android는 ‘손끝 영역 합성 적용 · 원본 지문선은 확인되지 않음’과 해당 영역 수를 표시한다. 기존 응답의 A/R 마스크·원본 결합·PNG 재읽기·부분 적용 표시·미검증 보호 플래그는 유지한다. **새 서버와 새 APK를 함께 사용한다.** 구버전 클라이언트나 서버는 추가 사유/경고를 거절할 수 있으므로 업그레이드 후 서버를 재시작한다.

기본 실행은 기존 서버/API 절차를 사용한다. 이전 정책의 CLI 비교는 다음과 같다.

```text
python ai/scripts/export_photo_permissions_v1.py --input <canonical.png> --output <fresh folder> --photo-engine synthetic_v23 --photo-model <V6 folder> --consumed-registry <registry> --request-id <unique id> --automatic-policy strict_ridge_v23
```

이 옵션은 `synthetic_v23`에만 유효하다. 독립 자료에서의 자동 영역 정확도·자연스러움·보호 효과 검증은 별도다.

## 실제 제공 사진

이전 정책에서 두 손끝이 지문선 관측 불확실로 미적용된 전체 사진을 새 정책으로 다시 실행했다. 검지·중지 2개 영역에 합성이 적용됐고 나머지 경계 불확실 후보 2개는 미적용이다. 적용 26,244픽셀 중 실제 RGB가 달라진 화소는 26,221개이며 적용 밖은 입력 RGB와 정확히 같다. 원본 관측은 두 손끝 모두 계속 불확실이다.

서버 처리 155.080초, 직접 호출·결과 재검사 포함 약 175.43초다. 일부 Android 검사와 겹친 단발 CPU 실행이며 120초 목표는 미달이다. 이 사진은 이미 디버깅에 사용했으므로 독립 평가로 집계하지 않는다. 원본·결과·실제 마스크는 비공개로 보존한다.

회귀·앱 검사 결과는 [작업 기록](../../docs/worklogs/2026-10-20-이봉헌-surface-policy.md)을 따른다.
