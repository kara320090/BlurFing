# 사진 입력부터 자동 보호까지 남은 차이

후속 갱신: 아래 내용은 자동 V23 연결 전의 차이 분석 기록입니다. 현재 Android 자동 연결은 [자동 V23 문서](PHOTO_AUTOMATIC_V23_20261020.md)에 따라 구현됐습니다. 미검출·가시성·독립 보호 효과·실물 장비/서버 검증 과제는 여전히 남아 있으며, [현재 시연 절차](../../demo/README.md)에서 확인합니다.

제품 목표는 Android 사진 입력 → 손끝 검출 → 지문선 가시성 판단 → 영역별 보호 처리 → 결과 저장이다.

현재 V23은 정해진 영역을 인공 지문 외관으로 교체하는 렌더러다. 최근 외관 개선 결과가 손끝 검출이나 자동 가시성 판정의 완성을 의미하지 않는다. Android/backend의 V2 계약은 V12/V13/V14만 지원하며 V23 연결은 별도 통합 작업이다. 일반 사진의 자동 보호 완료로 설명할 수 없다.

## 새 실행기에서 발견한 후보 소실

개발 사진 한 장에서 V6는 358,641 픽셀의 후보를 만들었고, 분리 손가락 보완 후 후보는 419,339 픽셀이었다. 둥근 경계 단계는 `rounded_tip_excluded_by_geometry`로 기존 후보를 보존했다.

이어진 주름 경계 보정은 신뢰할 수 있는 기하 기준점이 없는 후보를 보호용 허용 마스크에서 제외한다. 기존 알고리즘의 이 제한 자체는 유지해야 한다. 하지만 새 실행기는 이 제한된 마스크를 검토용 후보로 그대로 사용하여 0개 후보로 표시했다. 모델이 아무것도 찾지 못한 것과 UI에 검토 후보를 제공하지 못한 것은 다른 문제다.

수정 범위는 검토용 어댑터다. 보정에서 `unanchored_candidate_excluded`로 명시된 손가락 소속 영역의 기존 후보만 다시 제시하고 경계 불확실 경고를 기록한다. 다른 이유로 제거된 조각이나 소속 미확정 잡음은 복원하지 않는다. 없는 손끝을 임의로 생성하거나 모델 임계값을 낮추지 않는다. 원래 후보가 0개이면 그대로 0개다. 후보가 복구되어도 가시성 기본값은 불확실이며 보호 적용 권한은 생기지 않는다.

검증: 실행기 테스트 12개가 통과했다. 문제 사진의 실제 신경망 재실행에서도 후보 1개를 확인했다. 최종 소속 제한 규칙은 저장된 신경망 출력과 실제 경계 보정 코드를 재생하여 3개 사례를 확인했다. 첫 사례는 0→419,339 픽셀/1개 후보로 복구되었고, 나머지 두 사례의 231,297 픽셀/1개와 746,637 픽셀/4개는 동일하게 유지되었다. 신경망을 다시 실행한 검증과 저장 출력을 재생한 검증을 구분한다.

육안 확인에서 복구된 엄지 후보의 아래 경계는 사선이며 첫 관절까지의 정확한 보호 범위는 미확정이다. 후보 복구를 경계 정확도나 지문 보호 성공으로 해석하면 안 된다.

## 다음 우선순위

1. 후보가 소실되거나 원래 검출되지 않는 경우를 분리해 검증한다. 검출 성공은 손가락 전체의 정확한 보호 범위와 구분한다.
2. 지문선 가시성과 불확실 처리 정책을 제품 흐름으로 연결한다. 불확실 영역을 원본으로 반환하면서 전체 보호 완료라고 표시하면 안 된다.
3. V23 API와 Android 요청·좌표·결과 검증을 연결하고 실제 기기에서 실행한다.
4. 새로운 촬영 그룹으로 누락/과잉 영역과 처리시간, 원본 지문 잔존을 평가한다. 현재 개발 사진이나 합성 테스트를 독립 성능 수치로 사용하지 않는다.
