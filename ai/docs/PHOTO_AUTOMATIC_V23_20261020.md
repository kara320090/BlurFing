# Android 자동 V23 연결

Android 사진 입력 → 방향·sRGB 정규화 → V2 HTTP → 손끝 검출 → 경계 보정 →
반복 지문선 관측 → V23 합성 → 마스크·픽셀 검증 → 별도 PNG 저장을 연결했다.
AI는 PC/서버에서 실행되며 Android가 입력·요청·결과 검증·저장을 담당한다.
이 문서는 구현과 개발 검증 기록이다. 일반 사진의 완전한 보호나 독립 정확도 승인이 아니다.

## 원리와 변경 범위

- V6/COLFISPOOF/자세 보완의 기존 검출 결과를 사용한다. 기존 검토용 UI와 사람 정답은 유지한다.
- `synthetic_v23`은 별도 자동 선택 실험이다. 기하 경계가 확인된 후보에서 V11의
  원본 검사선 공동 반복 증거를 찾는다. 기존 주파수·봉우리·연결창 임계값은 변경하지 않았다.
- 영역 내부 bbox의 최대 변 640/1280, 최대 4,096개 유효 창을 검사한다.
  같은 해상도를 중복 검사하지 않는다. 연결된 양성 창을 발견하면 조기 종료한다.
  관측 실패·계산 예산 소진을 지문 없음으로 판정하지 않는다.
- 이는 보정된 가시성 분류기가 아니다. 기존 진단·사람 검토 결과를 자동 승인으로
  바꾸지 않고, 새 정책의 근거와 `automatic_visibility_approved=false`를 별도로 기록한다.
  일반 피부·직물의 주기적 무늬를 의미적으로 완전히 구별하지 못한다.
- 렌더링 공통 함수를 분리했다. 사람 검토형 진입점의 원본·마스크·사람 확인 계약은
  그대로다. 자동 경로는 사람 확인을 생성하지 않고 자동 선택 출처를 기록한다.

## 엄지의 방향 오류와 V24 경계 보완

주먹 형태의 BODY에서 전체 주축은 가로 방향이 될 수 있다. 기존 추정이 그 주축에
가까운 국소 축을 선택하면서 실제 세로 방향 엄지의 가로 축을 선택했다.
기존 너비도 전체 BODY의 영향을 받아 약 2,423.5px였고 주름 검사에 실패했다.

새 `photo_local_axis_v24.py`는 기존 경계가 확정되지 않은 소속 영역에만 적용한다.
손끝 후보의 PCA 축과 너비를 계산하고, 같은 소속 영역에서 후보를 제외한 부분의
중심 방향으로 근위 방향을 정한다. 타원형 모양을 강제로 합격시키지 않고 기존
RGB 주름 검사가 관측에 성공해야 실제 BODY 외곽을 보호 후보로 사용한다.
해당 사례의 너비는 528px로 계산되었고 관절 주름을 관측했다.
원래 성공했던 두 사례의 동일 seed 반환 RGB는 변경되지 않았다.

후보가 없거나 방향·관절이 불확실하면 원본을 유지한다. 새 기하 방식도 해부학적
정답이 아니며, 원형 후보·구부러짐·가림·프레임 잘림에서 실패할 수 있다.
일반 임계값이나 특정 사진 이름을 기준으로 성공하도록 맞추지 않았다.

## 통합 계약

- `photo_engine=synthetic_v23`, `method=photo_synthetic_v23_automatic_experimental`.
- 기존 V12/V13/V14는 유지한다. V23을 기존 native 검증기에 통과시키지 않고
  별도 region 단위 적용/복귀 및 실제 변경 검증을 사용한다.
- 응답은 기존 V2의 원본 해상도 A/R 마스크, RGB/파일 해시와 표시용 bbox를 따른다.
  서버와 Android가 적용 밖 RGB 보존 및 source/request/engine 결합을 다시 검사한다.
- `success`는 검출 후보의 처리 상태다. 전체 사진의 지문 누락 없음이라는 뜻이 아니다.
  미확인 입력 유형·후보 없음은 원본 반환/미적용으로 표시한다.
- Android의 V23 사진 선택은 자동 요청을 시작한다. 취소·사진 교체·엔진 변경 뒤의
  오래된 요청은 무효화한다. 복원된 과거 작업을 자동 재업로드하지 않는다.
- 입력은 15MiB/2,000만 화소 제한이다. DNG는 Android 지원 입력으로 검증하지 않았다.
  지문 전용 스캐너 경로는 이 자동 사진 엔진의 완료 범위에 포함하지 않는다.

## 실제 검증

- 실제 사진의 PC HTTP 처리: 후보 1개/적용 1개, 약 136초. 원본 해상도·마스크 밖 보존 확인.
- Android 에뮬레이터의 실제 Repository → HTTP → 모델 → V23 → MediaStore 저장/재읽기:
  1회 통과, 약 121초. 별도 실행 버튼 없이 사진 선택으로 요청했다. Mock 처리 아님.
- Android 단위 212개 통과·선택 시험 1개 skip, UI 회귀 11개 통과. debug APK 생성.
- 앱 첫 화면의 자동 진입점 → V23 선택 상태까지 별도 에뮬레이터 1개 통과.
- 백엔드 시험 105개 통과. 계약 schema의 추가 경고 enum/최대 개수도 별도 검사했다.
- AI 관련 단위·회귀 90개 통과. 실제 HTTP의 모호한 합성 입력은 200/rejected로
  원본을 반환하며 검출기 실행 오류나 보호 성공으로 표시하지 않는다.
- 기존 검출 출력 재생 3장: 6개 후보에 적용. 원래 엄지 0개 적용에서 1개 적용으로
  바뀌었고 다른 두 사진의 반환 RGB는 동일했다.
- 기존 6장 출력 재생: 후보 17개 중 16개 적용, 작은 후보 1개 경계 미확인.
  모델 재추론이나 독립 검증으로 집계하지 않는다. 원본/반환 축소 비교와 엄지 확대를 검토했다.

초기 Android 시험은 PATH에 들어 있던 큰따옴표 때문에 Java가 `Files`를 클래스 이름으로
해석해 실패했다. 실행 프로세스의 PATH에서 따옴표를 제거해 재실행했으며 시스템 환경을
수정하지 않았다. 새로운 엔진 enum으로 인한 시험 fixture 분기와 schema 경고 목록도 수정했다.

## 완료 판단에 남은 조건

사용자 요청으로 이번 검증은 에뮬레이터로 한정했다. 실물 휴대폰, 새 촬영 그룹의
경계·가시성 정답, 압축/재촬영/매칭 비교와 지속적인 서버 운영
검증이 남아 있다. 외곽의 작은 톱니·경계 누락 가능성과 2분 내외 CPU 지연도 남는다.
현재 결과는 자동 연동 가능한 개발판이다. `privacy_validated`,
`production_approved`, `complete_photo_protection_verified`는 false다.
기존 30장 반복 사용으로 독립 검증을 대신하지 않는다.
