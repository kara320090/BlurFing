# 상주 모델·손 영역 처리: 1분 목표 실측

## 결과와 범위

Windows i9-13980HX·RTX 4060 Laptop GPU에서 실제 HTTP로 측정했다.
모델을 준비한 서버에 3,000×4,000 RGB PNG를 보내고, 실제 응답을 검증한 뒤 PNG로 저장·재읽기했다.
기존 결과를 반환하는 캐시는 쓰지 않았고 매 요청 검출·합성을 새로 실행했다.

| 자료 | 서버 처리 | HTTP 수신 | 클라이언트 검증·PNG 재읽기 포함 |
|---|---:|---:|---:|
| 사용자 제공 V자 사진 1회 | 44.11초 | 44.38초 | **47.09초** |
| 같은 사진 2회 | 44.23초 | 44.61초 | **47.30초** |
| 인수 V자 사진 `TRN-022` | 64.50초 | 64.66초 | **67.15초 — 목표 초과** |

세 요청 모두 실제 AI로 손끝 2개를 합성했고 일부 후보는 미적용으로 남았다.
원본 해상도와 적용 밖 RGB 보존을 확인했다. **사용자 제공 사진에서는 60초 이내였으나 모든 사진에 대한 보장은 아니다.**
최초 서버 시작·모델/그래프 준비 **43.67초는 별도**다. 준비가 끝난 뒤 `/ready`가 성공한다.
콜드 스타트부터 첫 결과까지 60초라고 설명하지 않는다. 대기열·통신·실물 Android·학교 Ubuntu 시간은 별도 확인해야 한다.
두 자료 모두 개발에 사용했으며 독립 성능 평가로 세지 않는다.

## 바꾼 구조

1. `photo_resident_worker_v29.py`를 서버가 소유한다. Torch·의미 분할 모델·V23 경계 fit 프로세스를 준비하고 요청 간 재사용한다.
   의미 분할의 초기 그래프/커널 준비에는 합성 검정 영상을 사용하며 실제 사진 결과로 세지 않는다.
2. `photo_hand_roi_v30.py`는 전체 원본의 실제 MediaPipe 손 관측을 검증한 뒤 모든 관측 손을 포함한 영역과 여유 공간을 자른다.
   여유는 손 관측 범위의 긴 변 12%, 최소 32 원본 화소다. 이미지 축소·확대 없이 원본 격자를 유지한다.
3. 그 안에서 기존 COLFISPOOF 4방향·V6·자세·경계·가시성·V28 재질/V23 결합을 실제로 실행한다.
   손 사각형만으로 합성을 허가하지 않는다. 유효한 작은 손 영역을 얻지 못하면 전체 화면 경로를 쓰며 이때는 60초를 넘을 수 있다.
4. 적용 마스크와 RGB를 원래 좌표에 되돌려 기존 `synthetic_v23` 전송 계약으로 검증한다.
   적용 밖과 미적용 영역의 원본 RGB는 유지한다. Android 계약과 경고는 그대로다.

**검출 문맥은 바뀐다.** 손 영역을 잘라 모델에 넣으므로 기존 전체 화면 경로와 검출/적용 마스크가 같다고 주장하지 않는다.
첫 개발용 비교에서는 이전 두 손끝 적용 영역의 약 99.7%·98.0%가 새 적용과 겹쳤지만,
이는 초기 30% 여유 시험의 영역 비교일 뿐 최종 12% 여유의 정확도·자연스러움 점수가 아니다.
최종 HTTP 결과는 별도로 PNG·원본 보존을 검증했고, 일반 누락/오탐과 보호 효과는 미승인이다.

## 무손실·검증 비용 감소

- OpenCV PNG 인코딩은 RGB/마스크 샘플과 EXIF를 보존한다. ICC 등 추가 정보가 있으면 기존 인코더를 쓴다.
  빠른 RGB 압축이 15MiB를 넘으면 기존 압축으로 재시도한다.
- PNG 디코드 캐시는 매번 읽은 전체 인코딩 바이트의 SHA256으로 식별한다. 요청 종료·예외 시 제거한다.
- 파일 읽기 스냅샷은 요청 안에서만 재사용한다. 기존 호출자의 해시/출처 검사를 유지하며,
  응답을 내보내기 전에 각 파일을 다시 읽어 SHA256을 확인한다. 입력·추론 결과의 요청 간 캐시는 없다.
- 희소 마스크의 label/거리/홀 채우기는 필요한 작은 영역을 계산한 뒤 되돌린다. 지원하지 않는 서명은 원래 SciPy로 보낸다.
  작은 정수 집합의 membership 검사도 동일한 직접 비교로 처리한다.
- 의미 분할은 기존 nearest-neighbour가 선택할 라벨 좌표를 먼저 고른 뒤 class 검사를 한다.
  class 검사→nearest resize와 같은 결과임을 홀수 크기·4방향 합성 검사로 확인했다.
- AI 소스 전체 검증은 독립 파일 읽기만 병렬화했다. 파일별 전후 identity·SHA256·추가/삭제/심볼릭 링크 거절과
  V6의 동결된 학습 소스/가중치 검사는 유지했다.

## 활성화와 실패 처리

비공개 `photo` 설정에서 다음을 명시한다. 기본값은 둘 다 false다.

```json
{
  "resident_worker": true,
  "hand_roi": true
}
```

CUDA 장치·DLL 설정은 [이전 실행 설정](PHOTO_GENERATED_DETAIL_V27_20261020.md)을 따른다.
`hand_roi`는 상주 모드에서만 허용한다. 상주 모드는 `synthetic_v23` 하나로 제한한다.
`python demo/runtime.py serve --config <private-config> --service photo`는 상주 모델을 별도 일회성 프로세스에서 중복 로드하지 않는다.
실제 worker가 가중치·동결 소스를 읽고 모델을 준비한 뒤에 readiness를 표시한다.

동시 실행 1개·대기 1개·중복 요청 ID 거절을 유지한다. 각 요청은 새 임시 폴더와 별도의 내부 UUID를 쓴다.
시간 초과·취소·worker 종료·잘못된 응답에서는 소유 프로세스 트리를 회수한 뒤 임시 파일을 정리하고 worker를 다시 준비한다.
종료 확인에 실패하면 파일을 보존하고 런타임을 사용할 수 없게 한다. 준비 실패나 손 검출 실패를 이전 결과로 대체하지 않는다.

정확한 검사 범위와 남은 확인은 [작업 기록](../../docs/worklogs/2026-10-21-이봉헌-resident-photo.md)에 남겼다.
