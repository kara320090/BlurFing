# V6 체크포인트와 추가 입력 검증 코드 호환

2026-10-17 실제 합성 실행기의 detector→native→합성 경로를 점검하던 중 `completed_whole_pad_context_V6_development_checkpoint_required`가 발생했다. 학습 완료·프로토콜·임계값 조건은 모두 일치했으며 16개 학습 의존 파일 중 `pad_refinement_data_contract_v2.py` 하나의 해시가 달랐다.

`4d5ec82`는 이 파일의 `verify_source`에 `RGB_REFINED_BODY_V1`용 파생 마스크 계보 검증 분기를 추가했다. 이 정확한 분기를 제거한 바이트열이 직전 Git 버전과 같고, 직전 버전의 SHA256이 학습 기록과 같음을 확인했다. 기존 학습 입력의 분기와 모델 수학은 변하지 않았다. 파일 전체의 동일성만 허용하던 inference 검사가 추가 검증 분기를 모델 불일치로 거절한 것이 원인이다.

`infer_whole_pad_context_v6.py`는 다음 **정확한 한 방향 변경**만 명시적으로 허용한다.

- 학습 SHA256: `aa45082f18f3b9e7d90364bb4f420e5f930de28c71961df95669f494cb693f37`
- 실행 SHA256: `5d95e3fec9e5c47eeccecc2575ede5b342881aa46f4da6782279b31fd2757c1b`

다른 파일의 해시 변경, 파일 목록 변화, 알려지지 않은 버전, 역방향 변경은 계속 거절한다. 모델 파일·학습 설정·기존 해시 기록은 수정하지 않는다. 모델 해시·encoder 해시·프로토콜·threshold 검증도 유지한다. 실행 중 소스 변화는 학습 시점 해시 대신 실행 시작 시 실제 해시와 비교하여 거절한다. inference 기록에는 호환 사유와 실제 의존 파일 해시를 별도로 남긴다.

회귀 검사는 정확한 호환 경로, 학습 기록 바이트 보존, 다른 소스 변경 거절, 모델 로딩 도중 소스 변경 거절을 포함한다. 이는 알려진 추가 검증 분기의 호환이며 임의의 오래된 모델을 허용하는 정책이 아니다.

수정 후 관련 70개 테스트가 통과했다. Windows 실행기에 실제 사진 경로를 전달해 모델 로딩·손끝 검출·경계 보정·native 처리·합성 V4·최종 PNG 저장까지 완료했다. 출력의 허용 마스크는 기존 검증본과 같았으며 영역 밖 RGB와 원본 파일 해시를 확인했다. 모델 가중치 해시와 원래 학습 소스 해시 기록도 그대로였다. 대화형 파일 선택 UI는 재시험하지 않았다.
