# 가시성 마스크 수치 오류 수정과 공간 증거 실험

이 문서는 [V4 관측 비교](PHOTO_VISIBILITY_PEAK_TRAIN_V4_20261020.md)의 후속이다.
여기서 V4/V5/V6는 가시성 진단 버전이며 frozen 보호 V4나 합성 V19와 다르다.
기존 보호·실행기 조건과 사람 라벨은 바꾸지 않는다.

## 확정한 구현 오류

V2/V3/V4 진단은 AREA 축소 후 마스크 값이 `1-1e-12` 이상일 때만 창을
검사했다. 그러나 OpenCV의 보간 가중치 반올림 때문에 모두 1인 float64
영상도 약 `0.9999999404`가 된다. dtype을 float64로 지정해도 보간 가중치의
정확성이 그만큼 보장되는 것은 아니다.

558×285의 모두 유효한 마스크를 512×262로 축소한 재현에서 134,144픽셀 중
55,344픽셀이 잘못 제외됐다. 검사 창 전체가 유효해야 하는 조건 때문에 일부
실제 해상도 단계의 검사 창이 0개가 됐다. 이 숫자는 해당 환경의 재현 결과이며
다른 라이브러리 버전에서 동일한 오차 수를 보장하지 않는다.

`photo_visibility_support_v1.full_area_support()`는 **외부를 1, 내부를 0으로**
만든 뒤 같은 AREA 보간을 수행한다. 외부 기여가 정확히 0인 픽셀만 허용한다.
전체 내부에서의 0은 가중치 정규화 오차로 1 근처를 비교할 필요가 없다.
허용 오차를 확대하지 않으므로 작더라도 양수인 외부 기여는 허용하지 않는다.
양의 축소 크기, boolean support, 자원 제한을 검사하며 upsample을 허용하지 않는다.

`photo_visibility_peak_train_probe_v5.py`는 이 마스크 처리만 수정한다.
V4의 원본 profile·주파수·봉우리·간격·상관 조건은 재사용한다. V2/V3/V4 코드는
당시 실험의 재현을 위해 보존하고 이후 비교는 수정된 V5를 기준으로 한다.
과거 V2/V3/V4의 관측 수는 오류를 포함한 기록이며 최신 알고리즘 순위로 해석하지 않는다.

## 오탐·누락 감사

V4가 놓친 사람 보임 10영역과 사람 음성인데 신호가 관측된 1영역의 원본을
확인했다. 사람 표시·정답은 진단에만 사용했고 관측 함수 입력으로 전달하지 않았다.

- 미관측 10개 모두 통과한 개별 창은 있었다. 그러나 최대 연결 창이 1~3개로
  관측 조건인 4개에 도달하지 못했다. 주파수 방향 사전 검사 거절도 많았다.
- 원본 profile 검사를 세분하면 봉우리 4개 미만, 제안 간격과 실제 봉우리 간격
  불일치, 간격 변동 등이 나왔다. 가장 강한 주파수 가설에 대한 이 진단은
  실제 관측기의 모든 가설·최종 이유를 완전히 대체하지 않는다.
- 큰 주름이 표준편차를 지나치게 키웠다는 가설도 점검했다. 봉우리 부족
  profile 중 표준편차가 robust scale의 두 배를 넘는 경우는 일부에 그쳤다.
  이를 일반 원인으로 단정하거나 해당 사진에 맞게 prominence를 낮추지 않았다.
- 오탐 영역은 약한 세로 질감이 가까운 profile과 겹치는 검사 창에 반복됐다.
  여러 겹친 창은 독립 증거가 아니다. 사람이 확인하지 못한 지문이라고
  임의로 라벨을 변경하거나 이 사례를 제외하지 않았다.

## V6 실험의 설계

`photo_visibility_spatial_probe_v6.py`는 전체 Fourier ring의 방향 점수 대신
원본의 네 profile에서 반복을 확인한다. offset은 -6/-2/+2/+6픽셀이다.
기존의 주파수 범위, 가설 수 3개, 최소 봉우리 4개, 간격 변동·간격 일치·상관
상수는 유지했다. 공간적으로 더 넓은 확인을 요구하면서 혼합 방향에 의한
사전 거절을 줄이려는 별도 실험이며, 단순한 생산 임계값 완화가 아니다.

반복 구조와 비지문 질감을 완전히 구별하는 모델은 아니다. 같은 원본에서
얻은 네 profile도 독립 표본이 아니며, 후보 신호와 실제 가시성을 구분한다.
결과의 `automatic_visibility=uncertain`, `used_by_protection=false`,
`renderer_binding_allowed=false`를 유지한다. 관측 실패는 지문 부재가 아니다.

## 검증 절차

새 합성 시험을 통과한 뒤 V5/V6 코드·상수를 해시로 고정했다. 개발 23장을
먼저 실행하고 소비된 GT7을 마지막에 기록 재실행했다. GT7은 학습·조정에서
제외하고 결과를 보고 상수를 바꾸지 않았다. 자료와 과거 결과를 이미 보았으므로
전체 비교는 독립 또는 블라인드 검증이 아니다.

V5 native 단계는 V4와 동일한 마스크·원본·코드가 적용됨을 확인해 V4 측정값을
재사용했다. 이 단계의 반복 실행을 새 실험으로 세지 않는다. V5 축소 단계와
V6 전체는 실제 실행했다. 원본 캐시와 이전 결과의 연결 및 사람 주석 불변성을
검사한다. 신규 테스트 7개와 기존 회귀 72개, 총 79개가 통과했다.

신규 시험은 내부 마스크 보존, 외부 픽셀 유입 차단, 정수 기하 footprint와 비교,
실제 축소 양성 관측, native V4/V5 동등성, 약하고 휘어진 무늬·회전·큰 주름,
38개 잡음/비반복 대조, 결정성과 출력의 진단 전용 계약을 포함한다.

검증 환경은 Windows, Python 3.11.9, NumPy 2.2.6, OpenCV 5.0.0, SciPy 1.15.3이다.
이 환경은 예전 COLFISPOOF 전용 Python 3.10 환경과 다르다. Linux 동등성이나
다른 OpenCV 버전의 동일 오차 수를 검증한 기록이 아니다. 전체 다중 해상도
감사는 V5 재계산과 V6 실행을 합친 비용이므로 개별 엔진의 실시간 벤치마크로
사용하지 않는다.

```powershell
# ai/scripts 에서 실행
python -m unittest -v test_photo_visibility_support_v1 test_photo_visibility_spatial_probe_v6
```

수정된 V5는 이후 진단 기준이다. V6는 사람 음성 불일치를 줄여도 기존 보임
영역을 잃으면 사전에 정한 손실 없는 개선 조건을 만족하지 않는다. 방법별
좋은 결과만 사후 합치거나 비교 사진별로 방법을 선택하지 않는다.

개발 23장 비교에서 V4/V5는 사람 보임 44개 중 34개, V6는 28개를 관측했다.
V6의 추가 관측은 0개이고 관측 손실은 6개였다. 사람 음성과의 불일치는
1/6에서 0/6으로 줄었지만 이 손실 때문에 V6를 채택하지 않는다. 불확실 7개는
세 방법 모두 신호 미관측이다. V5에서도 오탐 1개·미관측 10개는 남았다.

남은 10개에서 V6의 검사 창 대부분은 네 원본 profile의 반복 조건을 채우지
못했다. 방향 사전 검사만 제거하면 해결된다는 가설도 지지되지 않았다.
이 결과는 현재 수작업 관측 특징의 한계이며, 실험을 PASS로 만들기 위해
봉우리·연결 창 수를 낮추거나 특정 사진을 예외로 처리하지 않는다.

새 독립 촬영 자료가 현재 불가능하므로 학습·교정·독립 검증 및 자동 보호 조건
연결은 보류한다. 기존 라벨링을 다시 요구하지 않는다. 촬영 그룹별 클래스
분포가 부족하다는 제한은 이전 [자료 준비 점검](PHOTO_VISIBILITY_REPETITION_V3_20261020.md)에 기록돼 있다.

## 전체 비교 완료 기록

30장·67영역 모두 완료했다. V5의 native 67단계는 동일성이 확인된 기존 측정을
재사용했고 축소 35단계는 재실행했다. 그중 31단계에서 기존 검사 창 0개 문제가
복구됐다. V6는 전체 102단계를 실행했다. 두 방법을 합친 진단은 약 1,000초로,
실행기 속도나 단일 방법의 공정한 벤치마크를 의미하지 않는다.

| 사람 판정 | 영역 수 | V4 | V5 수정본 | V6 실험 |
|---|---:|---:|---:|---:|
| 보임 | 53 | 43 | 43 | 37 |
| 관찰되지 않음 | 6 | 1 | 1 | 0 |
| 불확실 | 8 | 0 | 0 | 0 |

V5의 수치 오류는 수정됐지만 전체 영역 단위 관측 수는 같았다. V6는 추가 관측
없이 6개를 잃어 채택하지 않는다. 기존 결과 67개와 캐시 67개의 해시,
native 재사용 동일성, 사람 검토 상태, 보고서의 로컬 이미지 참조를 최종 확인했다.
오탐 1개·누락 10개가 남았으므로 모든 성능 문제가 해결됐다고 보고하지 않는다.
