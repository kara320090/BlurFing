# 합성 교체 V3 — 피부 위의 지문선 질감

V2의 피부 명암은 유지하되 너무 약하고 규칙적인 무늬를 바꾼다. 목표는 원본과 유사한 **사진 질감**이며, 원본의 식별 가능한 선 배치를 재현하는 것이 아니다. 원본에서 가져오는 정보는 V2와 같은 넓은 구역의 RGB 중앙값과 마스크 기하뿐이다.

## 구현

`photo_synthetic_replacement_v3.py`는 마스크 주축을 손가락 길이 방향으로 놓고 종횡비를 유지하는 512×512 좌표계를 만든다. 합성 간격은 그 기하와 독립 난수로 정한다. 관측된 원본 pitch로 보고하지 않으며 기존 pitch gate에 전달하지 않는다.

`photographic_ridge_field_v3.py`는 독립 난수와 아치·루프·소용돌이 방향장으로 Gabor 합성을 수행한다. 이 좌표계의 Y축은 손가락 길이 방향이며, Gabor 각도는 선의 접선이 아닌 법선이다. 아치 중앙의 법선을 Y축에 두어 손가락 길이 방향 줄무늬가 되는 문제를 피한다. 기존 frozen `ridge_structure_field.py`는 수정하지 않았다.

기존의 독립 변형 함수, `organic_ridge_profile.py`의 선 굵기·어깨·국소 대비 생성기, `independent_skin_relief.py`의 미세 피부 요철 생성기를 재사용한다. 이 함수들에는 원본 RGB를 전달하지 않는다. 생성 버퍼는 512 정사각형으로 제한한다. 피부 요철 함수의 4배 캔버스도 이 크기를 기준으로 하므로 원본 전체 크기로 확대 할당하지 않는다.

새 지문선 단면, 약한 방향성 명암, 독립 미세 요철을 저차 피부색 함수에 더한다. 경계에서는 생성 질감만 약하게 하며 원본 픽셀을 섞지 않는다. 마스크 밖 픽셀과 이미 승인된 기존 native 결과는 보존한다. 32픽셀 미만 또는 폭 4픽셀 미만 등 해상도가 부족한 영역은 작은 합성 질감으로 교체하고 `unresolved_texture_regions`에 별도로 기록한다. 이런 영역을 지문선 생성 완료로 보고하지 않는다.

## 사용

```text
python ai/scripts/replace_photo_synthetic_v1.py --input ORIGINAL --protection-run VERIFIED_NATIVE_RUN --output FRESH_OUTPUT --renderer v3
```

API/CLI 기본 V1과 `--renderer v2`는 유지한다. 합성 전용 실행기에서 V3를 선택한다. 기존 detector, native gate, `natural_auto_04`, `boundaryblend_02`, frozen V4는 수정하지 않는다. 기존 native의 거절을 성공으로 다시 분류하지 않는다.

## 검증 범위

같은 피부색 구역 안에서 원본 픽셀을 뒤섞어 지문선 배치를 없애도 동일 seed의 합성 결과가 같은지 검사한다. 이는 데이터 흐름 검사이며 일반적인 생체정보 보호 증명이 아니다. 재현성, 실제 파일 연동, 종횡비와 평행 이동, 마스크 밖 RGB, 작은 영역·빈 영역·구멍·불연속 영역·할당 제한을 검사한다.

6장 실험에서는 기존에 검증된 16개 경계와 V1 seed를 고정한다. 기존 detector/native 실행 결과를 재사용하며 새 독립 평가나 전체 실행기 체인 재실행으로 간주하지 않는다. V3 첫 시안의 세로 줄무늬는 육안 점검에서 발견해 법선 좌표계를 보정했다. 첫 시안 결과는 삭제하지 않고 새 폴더에 보정 결과를 저장한다.

원본과 같은 지문선이 남지 않는지, 자연스럽게 보이는지, 실제 인식 저항성이 있는지는 서로 다른 평가다. 피부 주름·경계 이음새·명암의 세부 표현에는 개선 여지가 있다. 독립 자료의 자연스러움 평가와 생체 보호 검증은 아직 완료되지 않았다.

2026-10-17 보정본 실행: 161개 단위·계약·회귀 테스트 통과. 6장·16개 지정 영역을 모두 합성했고 작은 영역으로 인한 질감 생성 불가 건수는 0이었다. 6장 모두 PNG 재읽기·영역 밖 RGB·원본 파일 해시·구역 내부 픽셀 순열 불변성 검사를 통과했다. 모든 영역 확대 화면을 검토했으며 굴곡과 분기가 보이지만 균일한 요철, 큰 피부 주름의 소실, 관절 쪽 이음새가 남는다. 실제 V3 CLI 1회와 실행기 PowerShell 구문 검사를 완료했다.

추가 인식기 비교는 이전 raw 회색조 결과를 보존한 채, 기존 `normalize_contactless`의 CLAHE 2.0/8×8을 원본·V1·V2·V3·검은 가림 모두에 동일하게 적용하는 별도 프로토콜이다. 모든 16개 영역의 bbox와 최대 내부 정사각형, 총 32개 ROI를 그대로 사용한다. 전처리·ROI·seed를 점수에 맞춰 탐색하지 않는다. 두 엔진에 각각 160개 ROI 이미지와 160개 비교를 요청한다. 실제 물리 DPI는 알려져 있지 않다.

두 엔진 모두 오류 없이 완료했다. 특징점 10개 이상인 양쪽 이미지와 정상 매칭 상태를 가진 원본→V3 비교는 다음과 같다.

| 엔진 / ROI | 비교 가능 / 전체 | 원본 자기 점수 중앙값 | 원본→V3 점수 중앙값 (범위) |
| --- | --- | --- | --- |
| NBIS / bbox | 13 / 16 | 68 | 0 (0–6) |
| NBIS / 내부 정사각형 | 1 / 16 | 100 | 3 (3) |
| SourceAFIS / bbox | 2 / 16 | 356.03 | 21.36 (7.23–35.50) |
| SourceAFIS / 내부 정사각형 | 2 / 16 | 338.55 | 0 (0) |

이는 개발 관찰값이다. bbox에는 마스크 밖 피부가 포함되고 내부 정사각형은 원본 특징점 부족이 많다. V2와 V3가 모두 비교 가능한 경우도 NBIS bbox 2개뿐이다. 따라서 버전 간 일반적인 보호 성능 우열·인식 차단율을 산출하지 않는다. 32개 ROI는 6장·16개 영역에서 만든 중복 범위이며 독립 표본 32개가 아니다. 점수 0·특징점 부족을 보호 성공으로 간주하지 않았다.
