# 가시성 V11–V13 비교와 사람 검토형 V19 연결

자동 관측 후보 세 개를 추가로 비교했지만 기본 진단을 교체하지 않았다.
별도 검토형 경로는 기존 사람 판정에 따라 **손끝 전체 마스크**를 V19로
처리한다. 자동 관측의 작은 증거 사각형을 보호 마스크로 사용하지 않는다.
기존 V5 진단, V9 후보, frozen 보호 V4, scanner, 합성 V19 수학은 그대로다.

## 자동 관측 비교

| 사람 판정 | 영역 수 | V5 | V9 | V11 | V12 | V13 |
|---|---:|---:|---:|---:|---:|---:|
| 보임 | 53 | 43 | 47 | 47 | 36 | 37 |
| 관찰되지 않음 | 6 | 1 | 0 | 0 | 0 | 0 |
| 불확실 | 8 | 0 | 1 | 0 | 0 | 0 |

숫자는 진단 신호가 관측된 영역 수다. 자동 분류 정확도나 보호 성공률이 아니다.
기존 30장·67영역을 재사용했다. 개발 23장·57영역을 먼저 비교하고, 후보를
고정한 뒤 기존 GT7·10영역을 역사 자료로 재실행했다. 음성은 두 사진·한 촬영
그룹의 여섯 영역뿐이며, 독립 검증으로 사용한 자료가 아니다.

- **V11**: 두 원본 검사선에서 같은 연속 봉우리 최소 네 개를 대응시킨다.
  상관은 그 공동 구간에서 계산한다. 서로 다른 구간의 반복과 큰 밝기 추세를
  같은 증거로 인정하던 약점을 줄였다. V9 누락 하나를 찾고 불확실 통과 하나를
  없앴지만, 기존 보임 하나를 놓쳤다.
- **V12**: V11에 더해 전체 Fourier 고리 대신 실제 관측 구간의 원본 기울기
  방향을 검사했다. 방향 계수 0.70은 재사용했으나 새로운 통계량으로서 미보정이다.
  기존 보임 열한 개를 놓쳐 채택하지 않았다.
- **V13**: V12의 방향 통계에서 일정한 조명 기울기를 제거한다. 봉우리 자체는
  여전히 원본 밝기에서 검사한다. 합성 조명 불변성은 확인했으나 실제 자료에서는
  V9의 보임 열 개를 놓쳐 채택하지 않았다.

사전 조건인 ‘누락 감소, 기존 보임 손실 없음, 음성·불확실 통과 증가 없음’을
사후 완화하지 않았다. 세 방법의 유리한 판정을 합치지도 않았다. V9도 자동
승인된 분류기가 아니며, 모든 관측 출력은 `automatic_visibility=uncertain`,
`renderer_binding_allowed=false`를 유지한다.

각 후보의 66영역은 모든 예정 해상도를 계산했다. 큰 역사 자료 한 영역은
완전 계산 비용이 과도해 작업을 중단한 뒤, 고정 코드의 첫 해상도에서 양성
증거를 다시 확인했다. 영역 판정은 해상도별 양성의 OR이므로 그 증거로 영역
판정이 확정된다. 음성에는 이 생략을 적용하지 않았다. **후보별 67영역 판정,
99해상도 계산, 나머지 3해상도 미실행**이다. 원래 계획·중단 기록·실행 변경
기록을 비공개 결과에 함께 보존했다. 전체 102해상도 재실행이라고 보고하지 않는다.

## 프로젝트에서 사용하는 검토형 경로

`photo_visibility_reviewed_apply_v1.py`와 `photo_visibility_reviewed_batch_v1.py`는
원본·마스크·좌표·검토 revision에 결합된 기존 사람 판정을 읽는다.

1. 검토 완료·사람 확인·모든 component의 판정을 검사한다. AI 제안이나 draft는 거절한다.
2. 사람 `visible`만 손끝 전체 마스크에 V19 합성 지문을 적용한다.
3. `not_observed` 및 `uncertain`은 원본으로 두고 각각 미적용·검토 필요로 기록한다.
4. 렌더러가 해결하지 못한 영역은 원본으로 되돌리고 적용 성공으로 세지 않는다.
5. 최종 PNG를 원래 EXIF 좌표로 저장하고 ICC를 보존한다. 재읽기 후 RGB를 검사한다.

사람이 여러 component를 하나로 묶은 경우에도 그 그룹을 하나의 적용·복귀
단위로 유지한다. 그룹을 component별 판정으로 다시 펼치면 일부만 처리됐는데
손끝이 처리됐다고 집계할 수 있었으며, 합성 재현 시험으로 이 오류를 확인해
수정했다. 현재 30장에는 합쳐진 그룹이 없지만 이후 검토 계약에는 필요하다.
배치 완료 직전에도 로스터 해시, 모든 선택 원본·마스크와 검토 revision을
다시 검사한다. 실행 중 변경된 자료를 이전 결과와 섞어 완료로 보고하지 않는다.

`synthetic_applied_unverified`는 합성 적용 상태일 뿐, 일반적인 지문 보호 승인이나
원본 지문이 완전히 제거되었다는 증명이 아니다. 검사 사각형, 후보 영역,
실제 적용 마스크와 실제 변경 픽셀 수는 서로 다른 값이다.

### 일괄 처리와 1픽셀 조각 오류

첫 적용 검증에서 매 사진마다 전체 로스터를 초기화하는 중복 읽기와,
8방향 연결 마스크의 대각선 한 픽셀이 V19의 4방향 연결 검사에서 별도 조각이
되는 문제를 발견했다. 후자는 정상 손끝 전체를 되돌리는 원인이 됐다.

- 검증된 `Project`를 일괄 실행 중 재사용한다. 로스터 경로·해시, 원본·마스크
  해시 및 각 사람 판정 revision 확인은 생략하지 않는다.
- 정확히 한 픽셀인 미해결 조각만, 같은 검토 손끝에 속한 즉시 인접 **생성**
  픽셀의 RGB 평균으로 보완한다. 원본·다른 손끝·멀리 떨어진 픽셀을 사용하지
  않으며 마스크를 늘리거나 보완을 연쇄 전파하지 않는다.
- 더 큰 미해결 조각은 계속 검토 대상으로 남긴다. V19의 미해결 메타데이터를
  덮어쓰지 않고 보완 픽셀 수를 별도로 기록한다.
- 중단된 배치의 `INCOMPLETE.txt`는 남는다. 완료 manifest가 없는 배치를 완료로
  취급하지 않는다. 기존 출력은 덮어쓰지 않는다.

### 큰 손끝의 별도 해상도 어댑터

실제 배치가 24장을 처리한 뒤 큰 손끝에서 `synthetic_region_pixel_limit`로
중단됐다. 기존 V19의 영역 4 MiPixel·bbox 8 MiPixel 제한은 유지한다.
`photo_reviewed_large_pad_v1.py`는 이 제한을 넘는 손끝만 별도 경로로 처리한다.

- bbox의 양 축을 같은 정수 거듭제곱 비율로 줄여 안전한 작업 면적을 만든다.
  실제 정수 크기·x/y 비율을 기록하며, 일반 크기 손끝은 원래 경로를 사용한다.
- `INTER_AREA`로 마스크 내부 RGB의 가중 평균만 계산한다. 마스크 밖 피부나
  배경이 작업 색에 섞이지 않는다. 그 작업 영상에 기존 V19를 그대로 실행한다.
- `INTER_LINEAR`로 **생성된 마스크 내부 값만** 가중 확대한다. 원본 RGB를 다시
  섞지 않고, 최종 원본 크기 마스크 내부에만 합성한다. 원본·마스크는 불변이다.
- 큰 영역의 V19 기하·질감 수치는 작업 좌표이며, 원본 좌표로 측정한 지문
  간격이 아니다. `working_resolution_adapter`가 좌표·크기·해상도 한계를 기록한다.

이는 메모리 제한을 올린 것이 아니라 별도 외관 복원 경로다. 확대 질감의
자연스러움·네이티브 세부 해상도·일반 보호 성능을 승인하지 않는다. 오류를
성공으로 삼키지 않으며, 정상 생성 여부·입력 불변·허용 영역 밖 보존을 확인한다.

## 실행

Windows PowerShell에서 기존 검토 로스터와 상태 경로를 지정한다. `OutputPath`는
새 폴더여야 한다. `SourceId`를 생략하면 검토된 로스터 전체를 처리한다.

```powershell
& "<repository>\ai\platform\windows\start_reviewed_visibility_apply.ps1" `
  -PythonPath "<environment>\Scripts\python.exe" `
  -RosterPath "<private>\roster.private.json" `
  -StatePath "<private>\state" `
  -OutputPath "<new-private-output>" `
  -SourceId "<reviewed-source-id>"
```

출력은 사진별 `returned.png`, upright 좌표의 `applied_mask_upright.png`,
`candidate_mask_upright.png`, `result.private.json` 및 `batch.private.json`이다.
이 경로는 기존 자동 실행기·Android 기본 엔진을 교체하지 않는 명시적 검토형 도구다.
새 사진은 별도의 원본·마스크 검토가 필요하다. 기존 30장은 다시 라벨링하지 않는다.

## 검증과 한계

새 관측 테스트 22개, 검토형 적용 14개, 큰 영역 어댑터 3개, AREA support 회귀
4개, V19 회귀 9개, 잔존 질감 진단 회귀 2개, 총 **54개 통과**. EXIF 8방향, 실제
렌더러·PNG 재읽기, 동일 seed, 입력·영역 밖
보존, 검토 출처·해시·partition 검증, diagonal 조각, 한 픽셀의 소유자 제한,
미해결 복귀와 배치 중단 표시를 포함한다.

동일 위치의 고주파 상관 진단은 원본 복사 징후를 찾아 검토하는 데만 사용한다.
신호가 없다고 원본 지문이 완전히 제거됐거나 독립 matcher에서도 식별되지
않는다고 판단하지 않는다. 경계 밖 누락·이동·회전된 복사까지 검증하지 않는다.

개발 matcher 비교는 기존 고정 프로토콜을 재사용한다. 사람 보임 그룹의
전체 bbox와 최대 내부 정사각형을 모두 선택하고, 동일한 512px 종횡비 보존
정규화·기존 CLAHE를 원본/실제 반환 RGB에 적용한다. DPI 500은 실험 가정이고
사진의 물리 DPI가 아니다. ROI·전처리·seed를 점수에 따라 선택하지 않는다.
원본 자기 비교, 원본→반환, 반환 자기 비교를 기록하고, 기존 양측 특징점
10개 이상 조건을 충족하지 못하면 불충분한 증거로 분리한다. 이 기준은 매칭
승인 임계값이 아니다. 동일 사진 자기 비교는 새 촬영 지문과의 식별 검증이 아니다.

개발 중 소스 무결성 시험과 코드 추가를 동시에 진행해 한 차례 검증이 중단됐다.
코드를 고정한 뒤 재실행해 통과했다. 이 실패와 첫 느린 배치의 일부 결과는
비공개 기록에 남겼다. 기존 버전과 원본을 삭제하지 않았다.

### 실제 30장 최종 실행

Windows PowerShell 실행기로 30장을 완료했다. 사람 보임 **53/53 그룹**의 전체
허용 마스크에 합성 처리를 적용했고, 관찰되지 않음 6개·불확실 8개 및 허용
영역 밖 RGB는 그대로였다. 대각선 보완은 총 2픽셀, 큰 영역 어댑터는 1영역에
사용했다. 원본·마스크 60개와 사람 검토 상태·실행 코드의 무결성을 확인했다.
이 수치는 사람 검토형 적용 완료율이며 자동 검출 정확도가 아니다.

67개 원본/반환 비교를 9개 모음 이미지로 검토하고, 큰 영역과 잔존 경고는
별도 확대해 보았다. 새로운 지문 무늬는 적용됐지만 일부 외곽의 각진 모양,
관절 경계의 단차, 매끈하거나 규칙적인 질감이 남는다. 전체 픽셀을 1:1로
육안 검사한 것은 아니며, 엄격한 자연스러움·정답 마스크의 완벽한 범위는
승인하지 않았다. 큰 사진 처리에는 수 분이 걸려 실시간 성능도 미달이다.

잔존 상관 진단의 사용 가능 창 1,172개 중 3개가 검토 경고였다. 모두 외곽·하단
경계와 겹쳤다. 기존 경계 밴드와 필터 범위를 제외한 보조 검사에서 2개는
원본 세부 정보 부족, 1개는 상관 약 -0.036이었다. 경계의 영향이 주요 원인으로
보이지만 원래 경고는 보존했다. 이를 원본 지문이 없다는 근거로 삼지 않는다.

SourceAFIS는 고정된 106 ROI·212영상·318쌍을 실제 처리했다. 원본→반환에서
전체 bbox는 44/53쌍 계산 가능, 점수 중앙값 0.992·최댓값 65.197이었다.
내부 정사각형은 34/53쌍 계산 가능, 중앙값 0.869·최댓값 18.093이었다.
나머지 각각 9쌍·19쌍은 불충분한 증거다. 전체 bbox에는 마스크 밖도 들어가며
내부 정사각형은 손끝 일부만 본다. 두 범위를 모두 기록했다. 이 점수로 일반
보호 성공률을 계산하거나 새 촬영과의 식별 불가능성을 주장하지 않는다.

NBIS는 첫 실행과 새 순차 재실행에서 각각 다른 단계의 Windows 프로세스
시작이 `WinError 5`로 거절됐다. 실행 파일 해시와 사용자 파일 권한은 정상이었고
원인은 확정하지 못했다. NBIS 검증은 **미완료**다. 실행 파일·보안 설정·평가
기준을 변경하지 않았으며 Windows 실행 제한의 원인 확인이 필요하다.

완전 자동 승인에는 새 촬영 그룹에서 가시성·경계 성능을 평가하고, 누락·불필요
적용·불확실 처리율 및 실제 반환 RGB의 잔존 지문을 확인해야 한다. 동일 개발
자료에 맞춘 반복 수정으로 그 검증을 대신하지 않는다. Linux 동등성·Android
통합·스캐너·독립 matcher 검사를 이번 작업에서 새로 완료했다고 주장하지 않는다.
