# 후보 마스크와 실제 가림의 차이 및 외부 모델 비교

2026-10-16 개발 기록. 개인 사진, 마스크, 학습 가중치는 비공개 작업 폴더에만 보관한다. 이전 결과는 [후처리 기록](PHOTO_COVERAGE_POSTPROCESS_20261016.md)에 있다.

## 세 손가락 사례의 원인

사용자가 보고한 동일 입력을 다시 실행하고 단계별 마스크와 실제 반환 RGB를 비교했다. 첫 화면의 Candidate는 COLFISPOOF/distal 추정의 coarse 후보이고, 최종 적용 마스크는 별도의 V6 예측이다. 후보가 최종 마스크에 반드시 포함되는 계약이 아니다.

- coarse 후보: 821,881화소. V6 예측: 482,659화소.
- 손가락 후보가 3개이므로 기존 **단일 손가락** coarse 보완 조건을 통과하지 않는다.
- MediaPipe는 이 입력에서 `no_hand_observed`를 반환해 자세 기반 보완이 없다.
- 닫힌 구멍 채움은 5화소만 복구했다. 열린 큰 틈은 닫힌 구멍이 아니다.
- 최종 마스크 482,664화소 중 coarse와 겹치는 부분은 478,830화소다. 후보의 **58.2603%**가 적용되고 343,051화소가 남는다. 화면 왼쪽부터 후보 적용률은 75.17%, 38.70%, 60.34%다.

새 V6 확률 추론도 저장된 예측과 일치했다. 47개 tile이 후보 영역을 모두 포함하며, tile 범위 밖으로 빠진 후보 화소는 0이다. 후보 중 343,056화소가 기존 0.5 판정 기준 아래였고 이후 구멍 채움이 5개를 더했다. 확률값이 보정된 신뢰도라는 의미는 아니다. 단순 좌표 손실이나 저장 실패보다 V6의 영역 과소 예측 및 보완 정책이 직접 원인이다.

최종 RGB는 원본에 최종 마스크만 검게 적용한 값과 정확히 같고, 마스크 밖 RGB와 EXIF 방향도 보존된다. Pitch-Free 경로이므로 지문 간격/특징점 거절 때문이 아니다. 후보 적용률은 모델끼리의 범위 일치도이며 사람 정답 recall, 지문 식별 저항성, 완전 보호율이 아니다.

## EdgeTAM 실측

[공식 EdgeTAM](https://github.com/facebookresearch/EdgeTAM)의 공개 checkpoint를 Windows CPU에서 실행했다. 소스 commit `7711e012a30a2402c4eaab637bdb00a521302c91`, checkpoint SHA256 `ed2d4850b8792c239689b043c47046ec239b6e808a3d9b6ae676c803fd8780df`. 코드·checkpoint의 Apache-2.0 조건을 확인했다. 중복 ImageNet 초기화 다운로드만 생략하고 최종 공식 checkpoint의 모든 state tensor가 일치하는지 확인했다.

기존 21장과 새 보고 사례 1장, 총 22장을 처리했다. 정답이 있는 13장은 V6 학습에 이미 사용된 개발 자료다. GT는 프롬프트 생성이나 후보 선택에 사용하지 않았다. 기존 coarse의 내부 점/근위부 음성 점/확장 박스 및 coarse dense prompt 두 가지를 고정하고, owner/coarse 제한 여부와 기존 마스크 합집합을 각각 평가했다. 모델 점수에 따른 사례별 선택이나 임계값 탐색은 하지 않았다.

| 방법 | 13장 합산 IoU | 정답 화소 recall | 과잉 가림 비율 | 퇴행 사진 수 |
|---|---:|---:|---:|---:|
| 기존 refined Coverage | 0.869647 | 0.909894 | 0.048400 | 기준 |
| EdgeTAM point + 기존 마스크 | 0.782399 | 0.917640 | 0.158510 | 11 |
| EdgeTAM dense + 기존 마스크 | 0.722910 | 0.922608 | 0.230422 | 12 |
| point를 coarse로 제한 후 합집합 | 0.866664 | 0.911145 | 0.053326 | 4 |
| dense를 coarse로 제한 후 합집합 | 0.729047 | 0.913813 | 0.217122 | 5 |

퇴행은 이미지별 FP 증가, recall 감소 또는 IoU 감소 중 하나라도 해당하는 경우다. 사전에 정한 채택 조건은 모든 GT13 사진에서 퇴행이 없고 실제 정답 화소를 복구하는 것이다. 네 합집합 후보 모두 조건을 통과하지 못해 적용하지 않았다.

보고된 세 손가락 사진에서는 dense/coarse 제한 결과의 후보 적용률이 약 99.2%로 늘고 검은 영역이 연속적으로 보인다. 그러나 다른 사진에서는 과잉 가림이 증가한다. 예를 들어 익명 사례 010의 FP는 기존 1,890에서 20,192화소로 늘었다. 이 사례 하나가 보기 좋다는 이유로 기본 모델을 교체하지 않았다. 이 사진 자체에 대한 사람 정답 경계는 없다.

22장 EdgeTAM 모델 비교 실행 시간은 약 61.53초였다. 데이터/마스크 읽기 및 진단 저장을 포함한 이 비교 스크립트의 시간이며, COLFISPOOF부터 시작하는 전체 제품 지연이나 Android 성능이 아니다.

## YOLO26 및 MobileNetV4 비교 방법

[YOLO26 semantic segmentation](https://docs.ultralytics.com/tasks/semantic)은 PNG 의미 분할 정답을 직접 사용할 수 있다. 손가락 instance 정답이 없는 현재 자료에서는 COCO instance `-seg` 모델 대신 `yolo26n-sem.pt`를 이진 손끝 분할로 추가 학습했다. 공식 Cityscapes checkpoint의 360/364 tensor를 이식하고 출력 분류층을 새로 학습했다. Ultralytics 8.4.178, checkpoint SHA256 `f3f293cca764de1f93044030d8d5612de9c5ffbf37c9c8ea1b69418b73038999`. Ultralytics 코드는 [AGPL-3.0](https://github.com/ultralytics/ultralytics/blob/main/LICENSE)이며 제품 배포 채택 시 이 조건을 함께 검토해야 한다.

MobileNetV4는 완성된 지문 분할 모델이 아니다. [timm의 ImageNet 사전학습 small backbone](https://huggingface.co/timm/mobilenetv4_conv_small.e2400_r224_in1k)에 새 다중 해상도 decoder를 연결했다. 이는 논문 저자의 공식 지문 모델이 아닌 timm 구현/학습 가중치와 이번 실험 decoder다. 사전학습 encoder 270개 tensor가 배포 가중치와 일치했고, 배포 가중치 SHA256은 `7a7102ec18f62bbfb555b6fe829bbb5af749516b84174926c29ffdfdfc03aec4`다. 모델 카드의 Apache-2.0 조건과 입력 정규화를 확인했다.

두 모델은 동일한 23개 개발 원본과 기존 3개 acquisition-group 분할로 평가했다. 정답 10장의 과거 visible-pad 경계 정책은 상세히 문서화되지 않았고 새 13장은 손끝 첫마디 전체 정책이므로 그룹별 결과를 함께 본다. 같은 촬영 그룹을 학습과 평가에 섞거나 원본 정답을 변경하지 않았다.

프로토콜은 실행 전에 저장했다: 전체 이미지 512 letterbox, area RGB/nearest GT resize, paired 90도 회전/좌우 반전, AdamW 0.001, batch 4, 40 epoch, BCE+Dice(YOLO auxiliary BCE 0.4), 최종 epoch만 평가, threshold 0.5. raw 출력과 관측 body로 제한한 출력을 각각 보고한다. 평가 자료는 gradient/epoch 선택에 사용하지 않았다. 원래 V6 비교치는 개발 검증에 따른 early stopping으로 선택된 OOF 결과이므로 학습 조건이 완전히 동일한 benchmark는 아니다.

채택 전 단계 조건은 전체/그룹 평균 IoU 개선과 모든 그룹에서 IoU·recall 비감소 및 과잉 가림 비증가다. 이를 통과할 때만 전체 자료 fit 및 기존 GT13 회귀 검증으로 진행한다. 이 작은 개발 비교만으로 모델 계열 전체의 성능이나 새 촬영에 대한 일반화를 단정하지 않는다.

### 실제 결과

| 방법 | 23장 사진 평균 IoU | 촬영 그룹 동등 평균 IoU | 기존 그룹 A IoU (7장) | 기존 그룹 B IoU (3장) | 새 첫마디 정책 그룹 IoU (13장) |
|---|---:|---:|---:|---:|---:|
| V6 저장된 OOF | 0.483604 | 0.470537 | 0.459142 | 0.447320 | 0.505149 |
| YOLO26 raw | 0.295182 | 0.360410 | 0.340970 | 0.522098 | 0.218162 |
| YOLO26 + 관측 body 제한 | 0.343755 | 0.389943 | 0.351675 | 0.519137 | 0.299017 |
| MobileNetV4 raw | 0.187870 | 0.213842 | 0.197828 | 0.283186 | 0.160513 |
| MobileNetV4 + 관측 body 제한 | 0.373916 | 0.326505 | 0.210587 | 0.287009 | 0.481919 |

두 모델 모두 채택 전 단계 조건을 통과하지 못했다. 따라서 새 모델의 전체 자료 fit, 기본 실행기 연결, production 승인은 진행하지 않았다. 특히 새 첫마디 정책 그룹에서 body 제한 후 사진 평균 recall은 V6 0.600338, YOLO26 0.328756, MobileNetV4 0.571006이었다. 기존 V6의 일반화도 충분하지 않으며 최신 모델 이름만으로 해결됐다고 보고할 수 없다.

두 모델 각각 3개 fold, 총 6개 학습/평가가 완료됐다. 손실·gradient·최종 가중치의 유한성, optimizer parameter 중복 부재, 학습 후 tensor 변경을 검사했다. 23장의 원본/GT/semantic 파일 해시를 재검사해 보존을 확인했다. 총 실행 약 752.73초는 CPU 학습·평가·마스크 저장 시간이며 제품 추론 속도가 아니다. Windows Python 3.11.9, Torch 2.14.1+cpu, timm 1.0.15, CPU 4 threads를 사용했다.

이 결과는 **고정한 초기 비교 설정**의 결과다. 서로 다른 학습 방식, 전체 영상 512 resize와 V6의 native tile 처리 차이, 적은 촬영 그룹과 정답 경계 정책 차이를 포함한다. 모델 자체가 다른 설정에서도 항상 열등하다는 증거가 아니다. 같은 개발 평가를 반복해서 최적 설정을 고르면 그 수치도 개발 결과이며, 새로운 독립 검증을 대신하지 못한다.

## 적용된 변경과 검증

`pitch_free_artifacts_v1.py`는 후보와 실제 적용 마스크를 명확히 구분하고, 후보 적용/미적용 화소 수와 비율을 반환한다. 빈 후보는 100% 성공이 아닌 `None`으로 기록한다. 비교 이미지와 로컬 실행기에도 실제 적용률을 표시한다. 이 변경은 마스크를 확장하거나 모델 판정을 바꾸지 않는다.

관련 테스트는 최종 **28개**가 통과했다. 실제 PowerShell 실행기로 같은 원본을 COLFISPOOF/V6/MediaPipe부터 재실행했고 original/protected/candidate/refined/learned/before-completion의 RGB·마스크·EXIF가 이전 실행과 일치했다. 기존 V6 모델과 설정 해시, 원본 입력이 보존됐다. 새 Linux/Android 실행 검증은 수행하지 않았으며 이전 테스트 수를 이번 실행 수에 합산하지 않는다.

추가 비교 이미지 저장 중 과거 사진의 ICC header가 632바이트를 선언하지만 payload에는 끝에 NUL 2바이트가 더 있는 사례를 확인했다. 기존의 길이 완전 일치 검사 때문에 `invalid_source_RGB_ICC_profile`가 발생했다. 이는 세 손가락 마스크 누락이나 과거 EXIF 오류의 원인이 아니다. `final_png_color_metadata_v1.py`는 이제 최대 3바이트의 NUL 꼬리만 허용하고, 선언된 길이의 실제 RGB profile을 CMM으로 검증한다. PNG에는 원본 payload 전체를 그대로 보존한다. 잘림·0이 아닌 꼬리·3바이트 초과·비 RGB profile은 계속 거절한다. [ICC의 추가 바이트 처리 안내](https://www.color.org/security/malformed/added-bytes/)를 참고한 제한적 호환 처리이며 모든 손상 profile을 허용하지 않는다.

합성 profile의 NUL 꼬리 1/2/3바이트, 손상/과도한 꼬리 거절, 원본/최종 RGB·EXIF·ICC 보존 및 색상 변환 동등성을 검사했다. 각 촬영 그룹의 첫 사진 3개에서도 실제 OOF 마스크를 RGB에 적용해 비교 PNG를 저장했다. 원본과 마스크 밖 RGB를 보존했고, 사람 GT는 비교 화면과 평가에만 사용했다. 이 결과들은 실제 제품의 채택 모델 출력과 구분해 개발 비교로 표시한다.

SAM 3는 공식 가중치 접근 승인이 없고, 사용자가 공개 모델부터 비교하도록 선택해 실행하지 않았다. 사용자 사진이나 학습 결과를 외부 서버로 업로드하지 않았다. 실험 의존성은 별도 작업 폴더에 설치했고 기존 실행기의 환경을 교체하지 않았다. 원격 push는 수행하지 않는다.
