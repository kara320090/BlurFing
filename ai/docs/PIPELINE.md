# 고정 파이프라인

1. 비공개 입력 이미지를 읽고 EXIF 방향을 적용합니다.
2. 자동 손끝 후보·관심 영역(ROI) 및 관측된 능선 간격을 처리합니다.
3. natural_auto_04 렌더러로 독립 합성 능선장의 외형을 생성합니다.
4. boundaryblend_02 합성기로 원본 바탕과 경계 세부 질감을 합성합니다.
5. 구조 검사와 실패 처리 계약을 거쳐 반환할 RGB 영상을 결정합니다.
6. NBIS에서 원본 자기 자신 및 원본→반환본을 평가합니다.
7. 같은 매칭 쌍을 SourceAFIS에서 별도로 평가합니다.
8. 관심 영역 메타데이터, 점수, 상태, 해시 및 감사 기록·결과를 기록합니다.

비공개 원본 입력 → EXIF 방향 적용 및 RGB 읽기 → 자동 손끝 후보와 원본 관측 능선 간격 → 독립 합성 능선장 → natural_auto_04 외형 프로필 → boundaryblend_02 합성기 → 기존 구조 검사 → 반환 RGB → 매칭 엔진별 결과 기록.

원본 골격이나 특징점을 합성 능선장에 복사하지 않습니다. boundaryblend_02는 원본 바탕을 유지하고 부호 있는 거리 기반 전이, 주름 완충 영역 및 잔여 질감을 사용합니다. 렌더러와 구조 검사의 수치 파라미터는 고정했습니다.

SourceAFIS 구조 검사 기준은 양쪽 특징점 >=10, 같은 좌표·종류 Dice <=0.9, 특징점 변화 >=2, 골격 XOR/합집합 >=0.05입니다. 실패한 영역은 원본을 반환하며 마스크 밖 픽셀을 보존합니다. 이 기준은 보호 효과 판정 기준이 아닙니다.

NBIS는 raw8/500 DPI → MINDTCT V2 → lfs2nist_format으로 전체 특징점을 추출합니다. MATCH 단계에서만 bz_prune(max150), min_computable_minutiae=10, BOZORTH3를 적용합니다. RAW 단계에는 150개 제한이 없습니다. 재시도 없이 오류와 insufficient_features 상태를 구분합니다.

SourceAFIS는 Java 11 대상 버전의 브리지와 Linux의 os.pathsep 클래스 경로 구분자를 사용합니다. 두 매칭 엔진 점수는 다른 척도로 별도 기록합니다. 실제 반환 RGB의 기존 너비 정규화 관심 영역 규칙을 사용하며 새로운 잘라내기 기준이나 임계값을 만들지 않습니다.

공개 사본은 사용하지 않는 과거 보조 진입점을 제외하고 필요한 함수와 직접·전이 사용자 정의 의존성을 포함합니다. 경로와 Linux 연동 구성만 공개 저장소 구조로 옮겼습니다. 개인정보 목록, 원본 영상 및 실행 바이너리는 공개하지 않습니다.

공통 nbis_matcher/sourceafis_matcher 인터페이스가 실행 중인 운영체제를 선택합니다. Windows는 같은 공통 알고리즘을 사용하며 출력 경로만 시스템 임시 폴더로 이동합니다.
