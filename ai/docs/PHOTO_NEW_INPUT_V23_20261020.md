# 새 사진 V23 로컬 테스트

기존 검토 목록 실행기와 별도로, 임의의 새 사진을 입력하여 후보 검출·경계 편집·가시성 확인·V23 적용·PNG 저장을 진행한다. 자동 보호 제품의 완료를 의미하지 않는다.

## 사용 순서

1. `start_new_photo_v23.ps1`에 Python 실행 파일과 결과 폴더를 지정한다. 자동 후보가 필요하면 V6 모델 폴더와 소비 자료 registry를 함께 지정하고 기존 COLFISPOOF/MediaPipe 환경변수를 설정한다.
2. 열린 로컬 화면에서 사진을 선택한다. 자동 검출을 실행하거나 직접 새 영역을 그린다.
3. 손끝 외곽부터 첫 관절 주름까지 경계를 확인한다. 다각형으로 추가·확장·축소·삭제할 수 있다. Enter는 완성, Esc는 취소, Backspace는 마지막 점 취소다. 이전 편집 되돌리기는 마스크와 가시성 판정을 함께 복원한다.
4. 각 영역을 `보임 / 관찰되지 않음 / 불확실`로 판정한다. 자동 후보는 모두 불확실로 시작한다. 경계가 변경된 영역은 다시 불확실로 돌아간다.
5. 원본 확대 확인 체크 후 V23을 적용한다. 보임으로 명시한 영역만 처리하며 불확실·미관찰·렌더러 거절 영역은 원본이다.
6. 원본/실제 저장 결과를 전환하고 결과 PNG를 다운로드한다. 화면의 저장 경로에도 결과가 이미 저장되어 있다. 화면의 종료 버튼으로 서버를 닫는다.

```powershell
& .\ai\platform\windows\start_new_photo_v23.ps1 `
  -PythonPath 'C:\path\to\python.exe' `
  -OutputRoot 'C:\private\new-photo-results' `
  -ModelPath 'C:\private\v6-training' `
  -RegistryPath 'C:\private\consumed_registry.private.json'
```

## 입력과 저장 계약

- 최대 40 MiB, 기존 32 MiPixels/최대 변/계획 메모리 상한을 적용한다. RGB/RGBA/8비트 회색조 JPEG·PNG를 지원하며 애니메이션 PNG와 기타 색상 모드는 거절한다.
- iPhone 등 복합 JPEG(MPO)는 기본 사진인 0번 프레임만 사용한다. 보조 프레임 수와 선택 정책을 기록하고 화면에도 기본 사진 사용을 알린다. HDR 보조 gain map을 합성하지 않는다.
- 원본 업로드 바이트를 보존한다. 파생 RGB는 EXIF 방향을 한 번 정규화하고 RGBA는 기존 흰색 배경 정수 합성 규칙을 사용한다. 해상도를 임의로 줄이지 않는다.
- 유효한 원본 RGB ICC 프로파일은 결과에 보존한다. 화면 표시본만 sRGB로 변환한다. 출력은 방향을 정규화한 RGB PNG이며 원본 EXIF 위치 등 개인 메타데이터를 복사하지 않는다.
- 마스크 밖 픽셀 보존 기준은 정규화된 RGB다. 원본 JPEG 압축 바이트 보존과 구분한다.
- 세션/사진/실행별 새 폴더를 사용한다. 이전 결과·원본·편집 이력을 덮어쓰지 않는다. 실패한 작업은 INCOMPLETE 표시 및 진단 기록을 남기고 완료 결과로 노출하지 않는다.
- PNG를 다시 읽어 RGB 해시·마스크·보임 영역 포함 관계·마스크 밖 동일성을 검증한다. 다운로드 대상은 실제 저장 PNG다.
- `user_confirmed_runtime_selection`은 실행 시 확인한 선택이며 학습 정답이 아니다. 기존 GT/roster/가시성 라벨/registry는 수정하지 않는다. 임의 새 입력을 독립 평가 자료라고 선언하지 않는다.

## 동작과 범위

자동 후보는 기존 V6 + 자세/분리 손가락 보완 + 둥근/주름 경계 경로를 재사용한다. 모델·임계값·frozen v4·V23 수학은 변경하지 않는다. 검출 실패 시 현재 수동 편집을 보존하며 수동 지정으로 진행할 수 있다.

실행기는 127.0.0.1 전용 토큰 경로와 정확한 Host/Origin 검사를 사용한다. 이미지 크기·요청 크기·좌표·버전·지역 중첩을 검증한다. 검출/적용 중 사진 교체와 편집을 막고 이전 버전의 요청은 거절한다. 후보 검출은 별도 프로세스이며 제한 시간은 600초다.

현재 한 번에 한 사진을 처리한다. 새로 실행한 서버에 이전 편집 세션을 가져오는 UI는 제공하지 않는다. 디스크에 남은 이전 결과는 보존된다. 자동 가시성 승인·독립 성능 검증·일반적인 보호 보장은 완료되지 않았다.

## Android 상태

이 화면은 PC의 로컬 테스트 UI다. 현재 작업본의 Android `ExperimentalPhotoEngine`과 backend V2 계약은 `native_v12`, `distal_v13`, `pose_v14`만 지원한다. `junction_v23`은 아직 해당 계약에 등록되지 않았다.

따라서 Android에 사진을 넣는 것만으로 이번 V23이 실행된다고 설명하면 안 된다. 다음 통합 작업은 V23용 서버 요청/응답 계약, 원본/마스크/판정의 결합 검증, Android 편집·확인 흐름, 실제 기기 업로드→처리→다운로드 검증이다. 확인 없는 완전 자동 모드는 별도의 가시성·검출 누락 처리 정책과 독립 평가가 필요하다.

## 검증

- 새 실행기 테스트 11개: EXIF 1~8, RGBA/L, MPO 기본 프레임, 잘못된 입력/중첩/좌표/이전 버전, 되돌리기, 저장 실패 롤백, 검출 실패/미확인 후보, 확인 없는 적용 차단, 실제 V23 렌더링, PNG 손상 검출, HTTP 계약.
- 기존 reviewed demo/apply, V23, PNG ICC/EXIF 회귀 테스트 38개 통과.
- 기존 개발 사진 1장을 새 업로드 경로로 입력하여 실제 외부 모델 검출 완료. 후보 4개, 모두 불확실로 시작함. 이 결과는 검출 정확도나 독립 성능 수치가 아니다.
- 브라우저에서 합성 PNG 파일 선택→다각형 1개 작성→보임 선택→확인→실제 V23 적용→PNG 다운로드를 확인했다. 다운로드 파일과 서버 저장 파일의 SHA256이 일치했다. 합성 UI 시험을 인간 정답이나 실제 지문 보호 검증으로 계산하지 않는다.
