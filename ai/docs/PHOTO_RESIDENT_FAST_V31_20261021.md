# V31: 사진 처리 지연 추가 최적화

## 최종 실측

Windows i9-13980HX·RTX 4060 Laptop GPU에서 현재 V27 재질과 실제 모델을 사용했다.
서버 준비 후 3,000×4,000 RGB PNG를 업로드하고 실제 응답 검증·PNG 저장/재읽기까지 측정했다.

| 입력/요청 | 서버 처리 | HTTP 수신 | 검증·PNG 저장/재읽기 포함 | 적용/미적용 |
|---|---:|---:|---:|---:|
| 제공 V자 사진 1회 | 34.25초 | 34.48초 | **37.26초** | 2/1 |
| 같은 사진 2회 | 34.91초 | 35.12초 | **37.76초** | 2/1 |
| 인수 V자 사진 `TRN-022` | 49.52초 | 49.73초 | **52.55초** | 2/1 |

이번 두 입력의 세 요청은 모두 60초 이내였다. **모든 사진의 1분 처리를 보장하는 결과는 아니다.**
최초 서버 시작·모델 준비 **43.69초는 별도**이며 사진 선택·최초 PNG 정규화 시간은 포함하지 않는다.
학교 Ubuntu·실물 Android·외부 통신/대기열 시간도 이번 Windows loopback 측정에 포함하지 않는다.
세 요청은 실제로 매번 검출·후처리·합성했고 이전 요청 결과를 반환하지 않았다.

직전 V27의 제공 사진 HTTP 기록은 49.87초·48.61초였다.
별도의 같은 작업 내 고정 시드 직접 실행에서는 두 번째 요청이 **45.14초→30.60초**로 줄었다.
첫 직접 실행은 프로파일러를 켜 44.89초→33.30초였으므로 프로파일러 없는 시간과 섞지 않는다.
직접 실행은 HTTP·독립 클라이언트 검증을 포함하지 않는다. 더 짧은 직접 실행 시간을 앱 전체 시간으로 쓰지 않는다.
이전 67.15초 인수 사진 기록은 V28 재질이므로 현재 V27과 엄격한 재질 동일 조건의 개선율을 만들지 않는다.

## 줄인 반복 비용

1. 공식 MediaPipe 1.1.1 CPU `IMAGE` 모드 검출기를 소유 프로세스에 준비한다.
   전체 사진과 손 ROI 모두 **해당 영상으로 새로 검출**하며 전체 사진의 좌표를 ROI 관측으로 대신 넣지 않는다.
   코드/공식 모델 SHA·입력/출력 결합과 매 요청 새 경로를 검사한다. 관측이나 처리 결과를 요청 간 재사용하지 않는다.
2. COLFISPOOF·손 모델·경계 fit 프로세스 준비를 겹친다. 준비가 끝나야 서버 readiness가 성공한다.
3. V6 체크포인트 객체를 재사용한다. 매 로드의 설정·동결 학습 소스·가중치 SHA·인코더 확인은 유지한다.
   캐시 hit와 작업 종료 때 **모든 파라미터/버퍼의 바이트 해시**를 검사한다.
   원래 모델 생성 후의 Python/NumPy/Torch RNG 상태도 복원한다. 학습 소스·가중치를 수정하지 않는다.
4. 손 ROI 안의 자동 처리는 결과 배열을 직접 넘긴다. 중간 PNG·base64 응답을 만들었다가 다시 읽던 경로를 없앴다.
   소스/후보/경계/런타임 검사는 유지하고, 원본 좌표에 결합한 최종 응답을 기존 전송 계약으로 검증한다.
   독립 호출의 기본 파일/응답 생성 동작은 유지한다.
5. 파일 `read_bytes`뿐 아니라 바이너리 스트림에도 요청 단위의 동일 파일 바이트 스냅샷을 사용한다.
   실제 파일 descriptor를 유지하며 각 검증기의 예상 SHA 검사를 그대로 실행한다.
   종료 전 실제 파일을 다시 읽어 SHA를 확인하고 모든 요청 캐시를 지운다.
6. 동일한 BODY/TIP 내용의 거친 영역 계산은 요청 안에서만 재사용한다.
   입력 전체 해시로 구분하고 출력 배열·메타데이터는 별도로 복사해 호출자 사이의 변경을 막는다. 상한 64MiB다.
7. 동일한 RGB/마스크·압축 설정의 PNG 인코딩을 요청 안에서 재사용한다.
   EXIF는 각 출력에 따로 결합하고 ICC 등은 기존 인코더로 보낸다. 인코딩 캐시는 64MiB 상한이다.
8. 상주 경계 fit 풀은 CPU 수 이내 최대 8개, 프로세스당 BLAS 1개 스레드로 제한한다.
   fit 계산식·반복 한도·결과 순서·96개 작업 상한은 같다. 별도 풀 없는 독립 실행의 기본 상한은 기존 4개다.
9. 소스 재파스/심볼릭 링크 검사는 한 번 얻은 `lstat`의 모드·속성 비트로 판단한다.
   같은 정보를 얻던 중복 시스템 호출만 줄였고 파일 집합·전후 identity·SHA 검사는 유지한다.

기존 디코드 192MiB·파일 128MiB와 새 거친 영역 64MiB·인코딩 64MiB 캐시는 각각 제한된다.
모델/fit 프로세스의 메모리는 별도이며 상주 프로세스를 유지하는 만큼 유휴 메모리를 사용한다.
취소·실패·시간 초과 때 소유 프로세스를 회수하는 서버 계약은 유지한다. 손 작업은 시작 시점 기준 60초의 대기 제한을 사용한다.

## 결과 유지 확인

같은 개발 사진과 시드 `20261020`의 직접 실행 두 번을 각각 변경 전과 비교했다.
반환 RGB·적용 마스크·후보 마스크·전체 사진과 ROI의 실제 손 관측값이 모두 정확히 같았다.
후속 소스 재파스 검사 중복 제거는 영상 알고리즘을 바꾸지 않는다.
실제 HTTP 세 요청에서도 적용 밖 원본 RGB와 최종 PNG 재읽기 검증을 통과했다.

실제 HTTP는 요청별 무작위 합성 시드여서 서로 다른 요청의 PNG가 같다고 주장하지 않는다.
V27 재질·원본 해상도·검출/가시성/거절 기준·COLFISPOOF 4방향·실제 합성을 유지했다.
사진은 개발 자료이며 검출 정확도·보호 효과·객관적 자연스러움의 독립 검증이 아니다.

활성화 설정과 앱 계약은 [기존 상주/손 ROI 설정](PHOTO_RESIDENT_ROI_V30_20261021.md)을 사용한다.
서버를 재시작해야 변경한 프로세스와 코드가 적용된다. Android API·APK 변경은 없다.
