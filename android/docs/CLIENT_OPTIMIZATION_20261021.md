# Android 앱 내부 최적화 — 2026-10-21

사용자는 기존 Play 앱에서 전체 동작이 3초 이내라고 보고했고, 서버를 직접 변경할 수 없다고 했다. 이번 변경은 **Android 앱 코드만** 수정한다. 학교 서버 설정·API·모델·처리 정책·출력 해상도는 바꾸지 않는다. 앱 버전은 1.0.4(5)다.

## 변경과 효과 범위

- 일반 보호 화면은 정규화한 선택 주소의 Repository 한 개를 유지한다. 재시도·다음 사진의 새 요청에서 OkHttp 연결 풀을 재사용한다. 사진·후처리 결과를 재사용하지 않는다. 주소를 바꾸면 새 Repository를 만들며 이전 서버로 다음 사진을 보내지 않는다.
- 사진 AI 화면도 같은 주소의 서버 확인과 처리에 같은 Service를 사용한다. 요청 ID·세대·취소·엔진 검증과 새 요청 실행은 유지한다. 최초 요청·프로세스 재시작·서버가 연결을 닫는 경우에는 연결 준비 시간이 다시 발생할 수 있다.
- 사진 AI PNG의 IDAT 읽기를 바이트 반복에서 청크 단위 복사로 바꾸고 inflate 버퍼를 512B에서 64KiB로 늘렸다. 필터를 행마다 선택하여 None/Sub/Up에 필요 없는 Average/Paeth 연산을 제거했다. 버퍼 증가분은 동시 두 reader 기준 128KiB로 메모리 계획에 포함했다.
- 원본·반환 PNG·마스크의 CRC, zlib 종료/남은 바이트, 행 수, 픽셀 해시·영역 밖 보존, 취소와 메모리 제한을 그대로 검사한다. 인코더·전송 형식·화질·이미지 크기를 변경하지 않는다.

두 화면의 경로는 별개다. 일반 보호 경로에는 연결 재사용이, 사진 AI 경로에는 연결 재사용과 PNG 읽기 개선이 적용된다. PNG 읽기 개선을 일반 보호 화면 전체의 속도 개선율로 설명하지 않는다.

## 국소 성능 측정

같은 Windows 개발 PC의 JDK 21, 단일 JVM, 합성 3000×4000 RGB PNG를 사용했다. 두 회 워밍업 후 다섯 회의 **행 읽기와 SHA256** 중앙값이다. 파일 읽기·PNG 구조 파싱·네트워크·AI·화면·저장은 포함하지 않는다. 변경 전 Kotlin class를 따로 보존하고 동일 harness·입력으로 비교했다.

| 합성 PNG | 파일 크기 | 변경 전 | 변경 후 | 감소 |
|---|---:|---:|---:|---:|
| filter 0 | 12,572,512B | 226.139ms | 158.978ms | 약 29.7% |
| filter 1 | 12,584,580B | 276.744ms | 208.660ms | 약 24.6% |

두 경로의 RGB SHA256은 `4b05580931ae3f4a556088e2903b61d9a48194237e1fab1d14fb8b68d219df8f`로 동일했다. 합성 입력은 seed 421의 1024×1024 RGB 타일을 반복해 3000×4000으로 자르고 filter 0/1·zlib level 1·64KiB IDAT로 저장했다. 실제 개인 사진·지문은 사용하거나 Git에 추가하지 않았다.

이 측정은 **실제 휴대폰 전체 처리의 25~30% 단축이나 1초대 완료를 의미하지 않는다.** 사용자 보고인 기존 3초 이내와 신규 앱의 시간을 같은 기기·사진·연결·처리 경로에서 비교해야 한다. 서버 대기/추론 시간은 이번 앱 변경으로 줄였다고 주장하지 않는다.

## 검증

- debug/release 각각 총 241개 중 **240개 통과·선택 검사 1개 건너뜀**, 실패·오류 0.
- 새 검사는 실제 로컬 TLS 연결의 두 요청 sequence 0→1과 서로 다른 요청 ID, 주소 변경 시 새 서버로의 전달, 사진 AI 준비 확인→처리 연결 재사용을 확인했다. 합성 서버 응답이며 실제 학교 AI 결과가 아니다.
- RGB/L의 다섯 PNG 필터, 1B/7B/64KiB IDAT 분할·빈 IDAT, 독립 픽셀 해시, 손상/압축 폭탄/여분 스트림 거절, 행별 취소와 메모리 제한을 검사했다.
- 첫 선택 실행에서 기존 HTTP 시험이 로딩 직후 자동 탐지와 수동 영역 편집을 겹쳐 요청 전 상태를 읽었다. 전체 실행에서는 기존 API 26 저장 권한 준비가 같은 상태 대기에 걸렸다. HTTP·저장·뒤로가기 시험이 자동 탐지 종료를 기다린 후 수동 영역을 편집하도록 고쳤다. 5초 제한과 실패·취소·권한 단언은 유지했다. 네이티브 그래픽 초기화 fixture도 유지한다.
- 첫 서명 빌드는 SDK 환경 변수가 없어 중단됐고 알려진 Android SDK 경로를 해당 빌드 프로세스에 지정해 재실행했다. 시스템 환경 설정은 변경하지 않았다.

이번 변경에서 실물 휴대폰 속도나 새 기기 UI 계측을 수행하지 않았다. 배포 파일의 서명·bundletool·Play 상태는 전달 폴더의 `release-verification.json`을 따른다. 기존 Play 설치 앱의 업데이트는 같은 내부 테스트 트랙을 사용한다. debug APK는 별도 시험용이며 기존 Play 앱의 동일 서명 업데이트 파일이 아니다.
