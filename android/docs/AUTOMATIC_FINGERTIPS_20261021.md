# 2026-10-21 일반 편집 화면의 손끝 자동 탐지

## 원인과 변경

사용자는 Play 1.0.2(3)에서 자동 탐지는 되지 않지만 ‘영역 추가’로 지정하면 처리가 된다고 보고했다.
일반 사진 편집 경로의 importImage는 영역을 빈 목록으로 만들었고 탐지기를 호출하지 않았다.
별도 V23 자동 처리 화면이 있어도 이 편집 경로에는 탐지가 연결되지 않은 상태였다.

1.0.3(4)은 사진 선택·촬영 직후 기기 내 손끝 탐지를 실행한다.
영역 없이 복원한 사진도 탐지하며 기존 수정 영역은 보존한다.
후보는 기존 NormalizedRegion 좌표로 표시하므로 이동·크기 조정·삭제·실행 취소와 기존 보호 처리를 사용한다.
‘손끝 자동 탐지’는 수동 영역을 유지하면서 덮이지 않은 후보만 추가해 중복을 줄인다.
탐지 중 수동 수정·사진 교체·화면 이동 시 요청을 무효화한다. 늦은 응답은 새 사진이나 수정을 덮어쓰지 않는다.
탐지 오류·손 없음에서는 가짜 기본 사각형을 만들지 않고 재탐지·수동 추가를 제공한다.
기존 V1 처리 설정과 별도 사진 V23 API를 변경하거나 서로 자동 대체하지 않았다.

  접힌 손가락을 기하적으로 제외하고 손끝 패드의 편집 가능한 사각형을 계산한다.
  거리·방향은 원본 픽셀 비율로 계산해 세로 사진·회전에서도 좌표 비율을 유지한다.

  흐림·가림·작은 손·접힌 손끝·손등에서는 누락이나 잘못된 후보가 가능하므로 화면에서 확인·수정한다.

## 실제 검증 범위

- 신규 단위 검사 13개 통과: V자 형태·접힌 손가락·회전·경계·잘못된 입력·중복,
  자동 시작·실행 취소·재탐지·수동 편집·사진 교체·초기화 후 늦은 결과·탐지 오류.
- 실제 APK의 CPU 모델 계측 검사 2개 통과. 단색 사진은 후보 0개이며 원본 비트맵을 보존했다.
  사용자가 제공한 기존 V자 사진에서는 후보 2개가 자동 추가되고 재탐지해도 중복되지 않았다.
  import→첫 탐지→재탐지 합계는 에뮬레이터에서 3493ms였다.
- 기존 자동 V23 화면·편집·뒤로가기·설정·공유·저장 UI 회귀 19개 통과.
- Android 17 프리뷰 API 37 에뮬레이터 결과다. 실물 휴대폰 속도, 새 촬영 자료의 검출 정확도,
  학교 서버의 보호 성공은 이 검사로 승인하지 않는다. 개인 입력과 좌표 보고서는 로컬에만 보관한다.
- 최종 서명 파이프라인 2분 47초 성공. debug/release 각각 236개 중 235개 통과,
  개인 입력용 선택 검사 1개 건너뜀, 실패·오류 0. lint 오류 0·경고 38·힌트 2.
  이전 업로드 키와 새 AAB 인증서 일치 및 jarsigner 검증을 확인했다.
- 첫 전체 검사에서 기존 뒤로가기·API 26 저장 권한 검사에 5초 시간 초과가 있었다.
  단독 재실행에서도 API 26 검사가 시간 초과했다. Robolectric의 첫 native Canvas/Paint 초기화를
  두 검사 모음의 준비 단계로 분리한 후 17개 재검사와 전체 debug/release 검사가 통과했다.
  5초 제한과 기존 단언을 바꾸지 않았으며 앱의 처리·저장 구현도 바꾸지 않았다.
- 실제 Play 업로드·출시 상태는 해당 배포 폴더의 검증 기록을 따른다.
