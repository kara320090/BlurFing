# 프로젝트 계획

프로젝트명은 BlurFing이며, 수업은 SW프로젝트응용(CapstoneDesign) 11분반이다.

| 주차 | 공동 목표 | 이봉헌의 개발 산출물 |
|---|---|---|
| 3주차 | 팀·역할·목표·요구사항 초안·저장소 준비 | 앱 사용자 흐름, 통합 요구사항 및 협업 구조 |
| 4주차 | 데이터·센서 가능성 점검, 기본 블러와 평가 엔진 확인 | 앱 설계, 한윤섭과 API 규격 공동 설계, 영역 좌표 계약 |
| 5주차 | 사진 입력부터 보호 사본 저장까지 MVP 연결 | Android·백엔드 1차 통합 버전 |
| 6주차 | AI 보호 성능 개선, JPEG 압축·축소 조건 비교 | 시연 화면, 오류·취소·재시도 처리, 통합 테스트 |
| 7주차 | 10월 16일까지 최종 산출물·보고서·발표 자료 완성 | 최종 통합 버전, 재현 절차, 사용자 흐름 검증·오류 해결 기록 |
| 8주차 | 발표·시연·질의응답 | 전체 사용자 흐름 시연, 직접 구현한 연동과 오류 개선 설명 |

## 역할 경계
이봉헌은 앱의 구현과 사용자 흐름 통합을 맡는다. 한윤섭은 서버 내부 모듈 연결과 API 구현을 맡는다. 공통 규격은 관련 담당자와 공동 설계한다. 유재윤은 알고리즘 성능 판단과 개선을 맡고, 이봉헌은 연결된 시스템이 정상·실패 상황에서 올바르게 동작하는지 검증한다.

각 팀원은 담당 코드·문서·실험 기록을 관리한다. 주 1회 통합 점검에서 남은 업무와 장애 요인을 확인하고 담당 범위 변경을 Issue에 남긴다. 회의록은 순환 작성한다.

## 개발 범위
정지 사진 보호 기능과 디지털 비교 평가를 우선한다. 실시간 동영상, 금융 인증용 생체감지, 물리적 지문 복제는 이번 MVP 범위에 포함하지 않는다. 기존 PC·학교 장비를 사용하며 유료 서버·GPU·SDK 구입을 전제로 하지 않는다. 신청서 예산은 이 저장소에서 변경하지 않는다.
