# 13. 사진 AI 실험의 결과 교체 확인

관련 요구사항: BF-04, BF-05, BF-06, BF-12. Android·시스템 통합 담당: 이봉헌.

사진 AI V2에서 변경된 결과가 아직 저장되지 않았다면 다른 엔진 선택, 다른 사진 불러오기, AI 재실행 전에 현재 결과를 바꿀지 확인한다. `계속 보기` 또는 확인창의 뒤로가기는 현재 원본·결과·엔진·서버 설정을 유지한다. `저장하지 않고 진행`을 선택한 경우에만 지정한 작업을 한 번 실행한다. 이미 선택된 엔진을 다시 누르면 현재 결과와 저장 완료 상태를 그대로 유지한다.

다른 사진 선택은 시스템 선택창에서 실제 URI가 반환된 뒤 확인한다. 선택창을 취소하면 추가 확인 없이 현재 결과를 유지하며, 교체 확인 전에는 새 사진을 읽거나 기존 결과를 지우지 않는다. 교체를 승인한 뒤 새 사진 읽기가 실패하면 기존 결과는 복구하지 않으며 오류와 재선택 안내를 표시한다. 원본 파일과 이미 저장한 사본은 삭제하지 않는다.

확인 대기는 ViewModel의 현재 세대·결과 객체·일회성 ticket에 연결한다. 이전 확인창의 늦은 응답과 중복 응답은 새 결정을 실행하거나 취소할 수 없다. 대기 중에는 다른 교체·서버 설정 변경·저장을 막아 결정이 덮어써지지 않게 한다. 입력·처리·저장·외부 저장 위치 선택 대기 중에는 엔진 변경과 재실행을 막는다. 처리 중 다른 사진 선택은 기존대로 현재 요청을 취소하고 새 입력으로 전환할 수 있으며, 이전 응답의 세대 검증을 유지한다.

화면 재생성은 같은 ViewModel의 대기 결정을 다시 표시한다. URI는 ViewModel에 application context와 함께 일시 보관하며 사진 픽셀·URI·실행할 작업을 saved-state Bundle에 추가하지 않는다. 프로세스 종료 후 사진·결과·대기 결정을 복원하는 기능은 아니다. 종료와 저장 완료 판단은 [12번 규칙](android-next-12-experimental-exit.md)을 계속 따른다.

이미 저장이 검증된 결과, 변경 없는 원본 반환, 결과가 없는 실패 상태는 별도 교체 확인 없이 진행한다. 검증은 합성 입력의 화면·상태 수명에 한정하며 AI 모델·API·실제 보호 성능을 바꾸거나 승인하지 않는다.
