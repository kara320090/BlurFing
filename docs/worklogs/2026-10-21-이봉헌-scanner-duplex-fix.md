# FFV 취득 결과 전송 멈춤 수정 — 2026-10-21

## 재현한 문제

0.2.1에서 취득기 경로를 바로잡은 후 사용자가 SupremaBioMini 모듈을 선택하고 손가락을 댔다. 센서 불빛은 들어왔으나 원본이 표시되지 않고 요청 시간 초과가 발생했다.

FFV helper가 동기 `NamedPipeClientStream` 하나에서 취소 감시용 `ReadByte()`를 대기하는 동안 결과 프레임 쓰기를 시도했다. Windows 동기 pipe I/O가 서로 막혀 결과 전달이 끝나지 않았다. 서버 처리 전의 로컬 전달 결함이다.

## 수정

- `PipeOptions.Asynchronous`로 pipe를 열어 취소 감시 읽기와 결과 쓰기가 독립적으로 진행되도록 했다. 같은 함수로 실제 취득과 SDK를 호출하지 않는 transport 검사를 수행한다.
- FFV 공개 결과 상태의 센서 미발견·취득 시간 초과·품질 실패를 구분해 표시한다. 성공 영상 조건이나 품질 기준을 낮추지 않았다.
- 마지막 시도의 단계·SDK 상태·오류 종류를 로컬 `last-attempt.log`에 기록한다. 지문·특징점·개인 DB·비밀번호·오류 전문은 기록하지 않는다.
- 0.2.2 비교 프로그램과 새 helper를 별도로 빌드했다. 기존 helper·개인 설정은 보존/백업하고 이 PC의 설정은 새 helper 경로로 바꿨다.

## 검증

실제 .NET Framework helper 소스의 pipe 옵션만 동기로 되돌린 별도 로컬 baseline과 수정 helper를 같은 프레임 검사로 비교했다. 센서·서버·지문 영상은 이 검사에서 사용하지 않았다.

| 검사 | 결과 |
|---|---|
| 동기 pipe baseline | 연결 후 2초 안에 결과 프레임 미수신 |
| overlapped pipe 수정본 | 올바른 BFSC2 취소 프레임 수신, 프로세스 시작부터 약 235ms |
| Windows 검사 | **27/27 통과** |
| 실제 Framework helper 양방향 회귀 검사 | 취소 읽기가 대기 중이어도 3초 제한 전 명시적 응답 수신 |
| Windows x64 자체 포함 EXE | 게시 성공, 버전 0.2.2, 코드 `65f7937` |

27개 검사는 합성 통신/영상 계약, 실제 설치 helper의 메타데이터·SDK 종속 파일 확인, SDK 호출 없는 Framework 양방향 pipe 검사다. 235ms는 전송 회귀 검사의 시간이며 실제 지문 취득·학교 AI 전체 처리 시간이 아니다. USB를 이용한 실제 취득·학교 서버 AI·SourceAFIS 점수 성공은 별도로 확인한다.
