# 2026-10-20 실제 실패 사진 수정·검증

사용자는 인수 자료의 실패 원인을 수정하고 새 V자 사진에서 두 손끝 처리·합성까지 확인하도록 요청했다. 기존 팀원의 V6 모델·V23 생성기는 유지하고 이봉헌의 인수 작업에서 자동 후보·손가락별 기하·경계 연결 코드를 직접 수정했다. 수정 전 기준은 `e7a2575`, 기능 수정은 `39bdfba`다. 원본·가중치·개인 경로·입력 해시는 공개 Git에 포함하지 않았다.

## 원인과 실제 수정

1. V자 사진에서 접힌 손가락의 `pose_axis_midpoint_outside_BODY`가 보이는 두 손가락까지 중단시켰다. 자동 경로에 손가락별 BODY·별도 semantic TIP·IP/DIP→TIP 검사와 제외 사유를 추가했다. 다른 원본/모델/worker 결합 오류는 계속 실패로 처리한다.
2. 실패한 자세 소유 ID를 다른 추정기 ID로 조회하여 `local_axis_owner_binding`이 발생했다. 서로 다른 소유 체계는 혼합하지 않고 복구 불가 자세 경계를 미적용으로 유지한다.
3. 부분 자세 선택이 다른 V6 후보를 지우지 않도록 미선택 손가락의 공간을 예약하고 기존 후보를 검토 대상으로 보존한다. 서로 닿은 후보를 소유 영역별로 분리하여 미확인 후보 때문에 유효한 이웃 전체를 거절하지 않도록 했다. 소유 라벨도 원본·제안 마스크와 해시로 연결한다.

이 변경은 [V25 기하 정책](../../ai/docs/PHOTO_PARTIAL_POSE_V25_20261020.md)이며 새 학습 모델은 아니다. API는 `synthetic_v23`을 유지한다. 특정 파일명 예외·사람 정답 마스크 주입·거절 기준 완화·유리한 시드 선택은 추가하지 않았다. 직접 비교는 사전에 고정한 동일 시드, 실제 HTTP 경로는 기존 자동 시드 정책으로 실행했다.

## 최종 코드 실제 실행

아래 모두 기존에 사용한 개발 자료다. 원본 JPEG의 방향·sRGB를 정규화한 전체 해상도 RGB PNG를 기존 API 계약으로 실행했다. 신경망·외부 모델을 새로 실행했으며 검출 캐시나 저장된 반환 이미지로 대체하지 않았다. 사람 마스크는 실행 후 평가에만 사용했다.

| 사례 | 수정 전 재현 | 최종 코드 결과 | 최종 측정 |
|---|---|---|---|
| V자 A | 자세 BODY 검사 오류로 중단 | 실제 HTTP 200, 후보 2·적용 2·거절 0, 서버 반환 PNG 저장·재읽기 통과 | HTTP/재읽기 약 136.14초 |
| V자 B | 서로 다른 소유 ID 조회 오류로 중단 | 후보 5·적용 2·거절 3. 보이는 두 손끝을 처리하고 미확인 후보를 남겨 `partial_success` | 직접 실행 약 124.30초 |
| 기존 성공 대조 | 후보 1·적용 1 | 계속 1개 적용. 같은 시드의 반환 RGB·적용 마스크·거절 마스크가 수정 전과 정확히 일치 | 약 116.54초 |
| 미관측 대조 | 소유 ID 조회 오류로 중단 | 후보 5·적용 0·거절 5, 반환 RGB 전체가 원본과 동일 | 약 112.77초 |
| 펼친 손 추가 진단 | 이번 수정 전 실행과 직접 비교하지 않음 | 후보 5·적용 3·거절 2. 보임 라벨 4개 중 1개도 가시성 불확실로 미적용 | 약 145.95초 |

**모든 사진의 처리를 해결한 결과는 아니다.** 펼친 손의 보임 영역 1개는 기존 raw-ridge 관측을 통과하지 못했고 미적용으로 남았다. 이를 통과시키기 위해 조건을 낮추지 않았다. 이 사례도 보고서에 포함했다.

V자 B의 기존 보임 마스크 두 개에 대한 적용 포함률은 약 97.77%·90.36%였고 불확실 마스크는 0%였다. 이는 기존 비독립 사람 마스크와의 기하 비교이며 실제 능선 누락률·보호 성공률이 아니다. 마스크의 해부학적 정확도와 적용 밖 잔존 지문은 별도 문제다. 전체 보호 플래그는 계속 false다.

최종 직접 실행 4개 모두 기존 서버 transport validator로 재검사하여 wire 계약·저장 PNG/응답 RGB 동일성·적용 밖 RGB 보존을 확인했다. V자 A는 실제 서버를 요청하여 같은 계약 및 디스크 재읽기를 검사했다. 후보 수는 해부학적 손가락 수가 아니다.

HTTP 증빙 도구는 1회 실행이며 120초를 넘었다. 종료 코드 2와 `three_consecutive_http_runs_within_120s=false`를 미달 표시로 유지했다. HTTP 클라이언트 단독으로 서버 추론을 보증하지 않으므로 원래의 attestation=false 필드도 바꾸지 않았다. 이번 실제 추론 기록은 별도로 설정·실행한 로컬 모델 서버에 근거한다. 진단 시간은 단발 실행이고 일부 회귀 검사와 겹쳐 통제된 속도 개선 실험이 아니다.

## 남은 작업

사용자는 새 V자 사진을 다음 메시지에서 제공하기로 했다. **새 사진을 받은 뒤의 첫 실행은 아직 수행하지 않았다.** 수정에 사용한 개발 자료와 구분하여 원본·양쪽 손끝·실제 적용/거절 마스크·결과 PNG를 보존하고 실패도 기록해야 한다.

일반 사진의 미검출/가시성·보호 성능, 120초 목표, 학교 Ubuntu·실물 휴대폰·센서의 연속 실행은 남아 있다. 이번 결과로 신원 매칭 확률이나 전체 사진 보호 성공을 생성하지 않는다. 학습·인수 원본·레지스트리·기존 `data/` 미커밋 5개 파일은 변경하지 않았다.
