# 센서 취득기 경로 수정 — 2026-10-21

## 문제와 변경

실제 PC에서 USB 센서가 정상 장치로 잡히고 학교 서버의 센서 준비 API도 응답했으나 비교 프로그램에서 취득을 시작하지 못했다. 개인 `settings.json`의 `ffv_helper`가 원클릭 FFV 취득기 대신 비교 프로그램 자신을 가리켰다. 기존 코드는 파일 존재 여부만 확인하므로 새 비교 창을 실행하고 90초 pipe 대기에 들어갈 수 있었다. 잘못된 개인 설정이 올바른 전달 설정보다 우선했다.

- 0.2.1은 FFV 선택 시 메타데이터의 원클릭 진입 코드와 전체 SDK 종속 파일·스캐너 모듈 폴더를 검사한다. 선택한 파일을 검사 목적으로 실행하지 않는다.
- 정상 개인 선택은 유지하고 잘못된 선택만 전달 설정의 정상 취득기로 복구한다. 취득 직전에도 검사한다.
- 비교 프로그램을 취득기로 실행하는 것을 거절하고 비교 프로그램 자체도 `--capture-once` 인자로 새 UI를 열지 않는다.
- 이 PC의 개인 설정은 원본을 백업한 뒤 기존 설치 SDK의 실제 취득기 경로로 수정했다. 개인 설정·SDK 파일·지문은 Git에 넣지 않았다.

## 검증

- Windows 검사 **25/25 통과**: 기본 계약·프로세스/pipe·취소·점수·저장 검사와 잘못된 실행 파일 거절, 설치된 공식 SDK의 기존 취득기 메타데이터 확인, 설정 복구, 종속 파일 없는 복사본 거절을 포함한다.
- 최초 검사는 실행 중인 구형 앱과 고정 legacy pipe가 충돌해 1개 시간 초과가 발생했다. 검사를 고유 이름의 pipe로 격리한 뒤 25개 모두 통과했다. 운영 앱의 기본 pipe 이름은 유지한다.
- Windows x64 자체 포함 단일 EXE 게시 성공. 코드 커밋 `9f95e83` 기준 0.2.1 전달본을 별도 바탕화면 폴더로 제공했다.
- Windows PnP: `Authentication Scanner (0x0408)`, USB VID/PID `16D1:0408`, 정상 상태, 설치된 Xperix 3.0.3.0 드라이버를 확인했다. FFV 취득기와 전체 SDK 종속 파일도 존재한다.
- 학교 서버: `/scanner/ready` HTTP 200, `scanner-comparison-v1`, `configured=true`, `inference_checked=false`. 지문 없는 `/scanner/v1/scanner/compare` POST는 HTTP 422 `INVALID_SCANNER_REQUEST`다. 해당 확인에서 지문 영상을 전송하지 않았다.

실제 손가락 취득·학교 서버 AI 처리·유효한 SourceAFIS 점수는 사용자가 수정본에서 취득 버튼을 누른 뒤 확인해야 한다. PnP 정상·설정 준비·합성 검사를 실제 지문 처리 성공으로 보고하지 않는다. 서버 코드·Android 앱은 수정하지 않았다.
