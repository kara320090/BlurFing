# 2026-09-28 이봉헌 — 카메라 촬영 입력 연결

담당: Android 앱·시스템 통합. 관련 요구사항: BF-02, BF-11, BF-12. 사용자 요청에 따라 추가 작업 중 카메라 촬영 입력 한 항목을 진행했다. Codex가 코드 작성·자동 테스트·빌드를 수행했다. 실제 스마트폰에서 촬영한 결과는 아니다.

## 변경 내용

- 첫 화면의 `카메라로 사진 촬영`에서 기본 카메라 앱을 호출한다. 전체 이미지를 받을 content URI를 전달하며 썸네일 반환에 의존하지 않는다.
- `CameraFileProvider`를 비공개로 등록하고 `cache/camera-captures/`만 공유한다. Intent의 출력 URI와 ClipData에 이번 촬영 파일을 지정하고 임시 읽기·쓰기 권한을 전달한다.
- 카메라 하드웨어를 직접 제어하지 않으므로 이번 변경에는 CAMERA 권한을 추가하지 않았다.
- `CameraCaptureViewModel`이 촬영 대기 URI를 SavedStateHandle에 보관한다. 중복 요청을 막고, 취소·카메라 앱 없음·실행 실패·빈 결과를 처리한다. 이미지 자체를 저장 상태 Bundle에 넣지 않는다.
- 촬영 성공 후 기존 SelectedImageLoader로 파일 크기·픽셀 수를 검사하고 EXIF를 보정해 영역 편집으로 이동한다. 현재 입력 한도 15MiB·2,000만 화소를 유지한다.
- 촬영 취소·실행 실패에는 임시 파일을 즉시 정리한다. 가져오기는 성공·실패·코루틴 시작 전 취소까지 완료 처리에서 정리한다. URI의 출처·전용 경로·파일명·정규 경로를 확인해 다른 파일을 지우지 않는다.
- 비정상 종료로 남은 앱 생성 파일은 다음 초기화에서 24시간이 지난 항목만 정리하고, 복원된 진행 중 촬영 파일은 보존한다.
- 촬영·가져오기 실패 화면에서 재촬영과 갤러리 선택을 제공한다. 준비 실패의 내부 파일 경로나 예외 상세는 화면에 표시하지 않는다.

## 검증

| 검증 | 결과 |
|---|---|
| 신규 CameraCaptureTest | 15개 통과. 출력 URI·Intent 권한·Manifest 경로, 중복 요청, EXIF 회전 입력, 취소·실행 실패·빈/손상 결과, 저장 상태 복원, 가져오기 시작 전 취소, 다른 파일 보호, 만료 정리, ViewModel 기본 생성, 준비 실패 정리 |
| Android 전체 회귀 검사 | 91개 통과. 실패·오류·건너뜀 0개. 기존 사진 선택·보호·저장·권한·통신 상태 검사 포함 |
| debug APK | assembleDebug 성공 |

검증 환경: Windows, JDK 21, Gradle 8.9, compileSdk 35, Robolectric API 28 Native Graphics. 테스트 사진은 작은 단색 합성 JPEG다. 손상 이미지 검사에서 decoder 오류 로그가 출력되는 것은 의도한 입력이다.

초기 테스트에서는 AndroidX FileProvider의 Android 경로 비교가 Windows의 역슬래시 경로를 해석하지 못해 파일 생성 단계가 실패했다. Windows 테스트에서만 URI 발급과 ContentResolver의 파일 I/O에 제어 가능한 대체 구현을 사용했다. 앱의 기본 구현은 실제 FileProvider를 사용한다. Manifest의 공유 범위와 Intent 권한은 별도로 검사했으며, 이 테스트가 Android의 실제 앱 간 권한 집행·카메라 앱 호환성을 검증한 것은 아니다.

```powershell
./gradlew.bat testDebugUnitTest --tests com.blurfing.app.CameraCaptureTest assembleDebug --max-workers=4 --console=plain
./gradlew.bat testDebugUnitTest assembleDebug --max-workers=4 --console=plain
```

## 기기에 남은 확인

1. 첫 화면에서 기본 카메라 앱을 열고 촬영 후 영역 편집으로 이동하는지 확인한다.
2. 촬영 취소·연속 클릭·카메라 앱 없음·빈 결과에서 재시도할 수 있는지 확인한다.
3. 촬영 중 화면 회전 및 앱 프로세스 재생성 후 같은 출력의 결과를 받는지 확인한다. 자동 테스트의 SavedStateHandle 복원은 이를 위한 모델 검증이다.
4. 기기별 JPEG 방향·고해상도 한도·촬영 앱의 자체 갤러리 저장 여부를 확인한다.
5. 합성 피사체로 촬영 → 영역 편집 → Mock 처리 → 비교 → 보호 사본 저장까지 확인한다.

사진 입력 후 편집 작업 전체의 프로세스 종료 복원, 비교 화면 확장, 팀 서버 실기기 연동은 이번 작업 범위가 아니다. AI·센서 실험은 실행하지 않았다.
