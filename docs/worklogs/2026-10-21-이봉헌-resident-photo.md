# 2026-10-21 이봉헌: 사진 처리 1분 목표 개선

사용자가 OpenCV나 실행 구조 변경을 허용하면서 60초 이내 처리를 요청했다.
기능과 검증/인계의 두 커밋으로 main에 전달한다. 기존 미커밋 data 5개 파일은 보존한다.

## 구현

- 서버가 실제 AI worker·COLFISPOOF 그래프·경계 fit 프로세스를 준비하고 재사용한다.
- `resident_worker`와 `hand_roi`를 명시적으로 설정한다. 기본은 false이며 현재 Android 전송 계약은 같다.
- 전체 원본의 MediaPipe 관측을 출처 검증한 뒤 손 전체와 여유 영역을 원본 격자로 자른다.
  여유는 관측 손 범위 긴 변의 12%, 최소 32화소다. 그 안에서 기존 의미 분할 4방향·V6·자세·경계·합성을 실행한다.
- 원래 좌표와 해상도로 합성 결과/마스크를 되돌리고 기존 전송 검증을 수행한다.
  ROI 사각형 자체가 합성 허가는 아니며, ROI를 얻지 못하면 전체 화면 경로를 사용한다.
- OpenCV 무손실 PNG·요청 단위 디코드/파일 읽기 스냅샷·희소 마스크 계산·동일한 class/nearest 선택 순서로 반복 비용을 줄인다.
  요청 종료 전에 파일을 다시 읽어 SHA256을 검증하고 캐시를 제거한다. 결과를 요청 간 재사용하지 않는다.
- 전체 AI 소스의 파일별 전후 identity/SHA 검사는 독립 읽기만 병렬화했다. 동결 V6 학습 소스·가중치 검사는 유지한다.
- 원래 요청 제한(실행 1·대기 1), 새 임시 폴더, 내부 UUID, 외부 요청/원본/마스크 결합 검증을 유지한다.
- 취소·시간 초과·worker 종료/잘못된 프레임은 소유 트리를 회수한 뒤 정리하고 다시 준비한다.
  종료 확인 실패 시 파일을 보존하고 unhealthy로 처리한다.

## 실제 측정

Windows i9-13980HX·RTX 4060 Laptop GPU, 실제 모델, 실제 loopback HTTP를 사용했다.
클라이언트 입력 PNG는 3,000×4,000이다. 아래 전체 시간은 업로드 시작부터 반환 검증·PNG 저장/재읽기까지다.
클라이언트의 사진 선택/최초 PNG 변환이나 실물 Android 시간으로 설명하지 않는다.

| 자료 | 서버 | HTTP 수신 | 검증·PNG 재읽기 포함 | 적용/미적용 |
|---|---:|---:|---:|---:|
| 사용자 V자 1회 | 44.11초 | 44.38초 | **47.09초** | 2/1 |
| 사용자 V자 2회 | 44.23초 | 44.61초 | **47.30초** | 2/1 |
| 인수 V자 `TRN-022` | 64.50초 | 64.66초 | **67.15초·초과** | 2/1 |

최초 서버 준비 **43.67초는 별도**다. 준비 전/후와 콜드·웜 요청을 혼동하지 않는다.
두 사용자 사진 실행은 60초 이내였지만 모든 입력의 1분 보장은 아니다.
인수 사진의 초과를 숨기거나 셋 모두 통과한 것으로 집계하지 않는다.
각 요청은 실제 검출/후처리를 수행했고 적용 밖 원본 RGB·전송/PNG 재읽기 검증을 통과했다.
두 입력 모두 개발 자료이며 독립 검출 정확도·보호 효과의 근거로 쓰지 않는다.

초기 상주화/입출력만으로 약 106·91초가 나와 충분하지 않았다.
손 ROI 여유 30% 시험에서는 사용자 사진 48.6·50.3초, 인수 사진 69.4초였다.
최종 12% 여유에서도 인수 사진은 67.2초로 남았다. 특정 사진 예외나 좋은 합성 시드 선택은 추가하지 않았다.
서로 다른 계측 조건의 옛 132초와 새 HTTP 시간을 이용해 개선율을 만들지 않는다.

ROI로 모델 문맥이 달라지므로 전체 화면 기준과 마스크/RGB가 같다고 주장하지 않는다.
초기 고정 시드의 비교 이미지도 비공개로 남겼고, 최종 실제 HTTP 결과는 별도로 저장했다.
자연스러움·전체 사진의 누락 없음·일반 보호 효과는 여전히 미승인이다.

- AI 기하/선택/재질/무손실 IO/ROI 공개 pytest: **69개 통과**, 하위 검사 6개 통과.
- demo 설정 pytest: 새 검사 삽입 위치의 NameError를 수정해 **34개 재검사 통과**.
- backend 전송·실행 및 새 상주 프로세스 수명 주기: **168개 재검사 통과**, 하위 검사 59개 통과.
- 실제 AI Python의 기존 export/transport/pose/성능/검토/경계/전체 소스 계약 unittest: **131개 통과**.
- 새 IO·마스크·의미 분할·ROI 및 소스 검사 묶음은 실제 AI Python unittest **28개 통과**이며 위 검사 일부와 겹친다.
- 최초 source 검사 6개는 Torch 없는 demo 환경에서 실패했다. Torch 환경에서 다시 실행했다.
  AI Python에 pytest가 없어 unittest로 실행했으며, 미실행을 통과로 바꾸지 않았다.
- 동시 회귀 중 취소 시험에서 wait 완료 경합 뒤 취소가 다음 대기 단계로 넘어가는 현상을 발견했다.
  단계 사이 현재 task의 취소 상태를 재확인하고, 완료 경합을 직접 재현하는 검사를 추가했다.
  단순히 제한 시간을 늘려 숨기지 않았다.
- 기존 Starlette/httpx 사용 중단 예고 경고는 남고 검사 실패는 해소했다.
- 동결 학습 파일·가중치·요청별 새 추론·원본/마스크 결합·최종 파일 SHA/AI 소스 검사를 유지했다.
