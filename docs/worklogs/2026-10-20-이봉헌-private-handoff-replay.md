# 2026-10-20 비공개 인수 자료 복원과 실제 V23 재현

초기 시연 도구 구현 이후 사용자가 비공개 인수 자료를 전달했다. 기존 팀원의 V6 학습·V23 합성 구현을 사용했으며 이번 작업은 이봉헌의 환경 인수·실행기 수정·통합 검증이다. 사진·지문·가중치·원본 해시·개인 경로·Drive 식별자는 이 기록과 공개 Git에 포함하지 않는다.

## 인수·환경 재현

- 사용자가 다운로드한 ZIP에는 28개 전송 항목이 있었다. 다운로드 과정에서 첫 조각 5개에 붙은 추가 `.zip` 확장자는 인수 체크섬과 일치하는 복원용 사본에서만 정규화했다. 사용자 원본 ZIP은 변경하지 않았다.
- 전송 파일 27개 체크섬, 분할 조각과 9개 원본 ZIP, 복원한 **2,251개 논리 파일**의 해시를 검증했다. 같은 내용의 중복 복원 경로를 포함하며 독립 사진 2,251장이 아니다.
- V6 모델·대응 설정·사용 자료 레지스트리, COLFISPOOF·MediaPipe 가중치와 기존 기준 결과를 확보했다. frozen config와 과거 절대 경로 기록은 편집하지 않고 실행 경로를 별도 private 설정으로 연결했다.
- Python 3.11.9의 AI 환경과 Python 3.10.11의 COLFISPOOF/MediaPipe 환경을 분리하고 전달된 패키지 버전을 설치했다. Torch 2.14.1+cpu·torchvision 0.29.1+cpu, TensorFlow 2.10.0·NumPy 1.21.6, MediaPipe 1.1.1을 확인하고 환경별 `pip check`가 통과했다.
- Python 3.10은 공식 서명이 확인된 프로젝트 전용 휴대용 runtime을 사용한다. COLFISPOOF 공식 Git 모듈은 기존 공개 기록과 같은 Git blob bytes로 연결했다. 시스템 Python·사용자 원본·가중치 승인 플래그는 변경하지 않았다.
- 기존 V6 validator의 protocol·학습 의존 소스·checkpoint·encoder 검사가 통과했다. 자산 검사는 실제 추론과 구분했다.

## 실제 실행과 확인 범위

실측 기준 코드는 `db0bb4b`이며 AI 알고리즘은 인수 기준 `6e1a57b`와 같다. 이후 수정은 센서 실행기의 플랫폼별 runtime 연결이며 PHOTO 알고리즘은 변경하지 않았다.

| 검사 | 결과와 한계 |
|---|---|
| 기존 개발 사진 1장, 고정 시드 실제 전체 추론 | 반환 RGB·적용 마스크·거절 마스크가 인수 기준 결과와 모두 정확히 일치 |
| 첫 재현 실행 | import 포함 약 166.43초, 후보 1·적용 1·거절 0 |
| 라이브러리 스레드 1 조건 추가 실행 | 약 153.05초, 반환 RGB·양쪽 마스크 모두 정확히 일치. 서로 다른 조건의 각 1회이므로 일반적 속도 개선 효과를 확정하지 않음 |
| 단계 측정 | 후보 준비 약 99.78초, 그 안의 COLFISPOOF child 약 39.05초, 경계 복구 약 5.76초, 적용 약 34.48초 중 합성 약 32.63초. 중첩된 단계이므로 전부 합산하지 않음 |
| Android Repository→실제 loopback 서버→모델→저장 재읽기 | API 37 에뮬레이터 1회 통과, 앱 경로 측정 약 177.06초. 실행기 전체 시험은 약 182.24초 |
| Android 입력 경계 | 미리 정규화한 3024×4032 canonical PNG를 사용한 opt-in 검사. 일반 JPEG 갤러리 입력·실물 카메라·휴대폰 시험으로 확대하지 않음 |
| 별도 HTTP 증빙 도구 실제 1회 | HTTP 200, 픽셀·마스크 계약과 저장 재읽기 통과, 약 158.22초. `--runs 1`이므로 3회·120초 게이트는 false이며 종료 코드 2를 정상적인 미달 표시로 유지 |

실제 모델을 새로 실행했으며 기존 검출 캐시나 저장 반환 이미지로 요청을 대체하지 않았다. 고정 시드는 재현 비교에만 사용했고 HTTP 자동 경로에는 시드 필드를 추가하지 않았다. 이미 사용한 개발 사진의 명시적 DevelopmentReplay이며 독립 평가가 아니다.

**이 PC에서 120초 목표는 아직 충족하지 못했다.** 인수 파일이 확보됐다는 사실이 검출 일반화·전체 지문 보호 성능을 개선했다는 뜻은 아니다. 학교 Ubuntu에서 동일한 입력·환경·측정 범위로 단계별 시간을 확인한 뒤 수정 우선순위를 결정한다.

## 실행기 후속 수정·회귀

센서 실행 환경이 NBIS Linux 설정만 전달하던 문제를 발견했다. Windows는 `BLURFING_NBIS_WINDOWS_CONFIG`, Linux는 `BLURFING_NBIS_LINUX_CONFIG`를 선택하고 다른 플랫폼 및 일반 설정의 오래된 값을 제거한다. scanner probe는 모듈 import에 더해 기존 NBIS 실행 파일 형식·해시와 SourceAFIS 의존 runtime 검사를 호출한다. 입력 파일이 있다는 이유만으로 준비 완료로 처리하지 않는다.

Windows/Linux runtime 바인딩 검사를 포함한 **시연 도구 합성 회귀 32개가 통과**했다. 앞선 [전체 준비 검사 기록](2026-10-20-이봉헌-demo-handoff.md)의 단위/에뮬레이터/AI 합성 검사는 해당 단계의 결과이며, 이번 실제 모델 실행 수와 합산하지 않는다.

## 남은 완료 조건

- 10월 21일 학교 Ubuntu 실제 설치·연결과 최신 모델 동등성·지연 측정.
- 실물 Android의 일반 사진 입력부터 저장·재읽기 연속 3회, 각 120초 이내.
- 실센서 FFV→학교 서버→실제 처리·유효 점수→저장 연속 3회. NBIS·SourceAFIS runtime은 인수 묶음에 없으며 별도 준비·검증이 필요하다.
- 새 사람·촬영 그룹의 개발/평가 분리, 미검출까지 포함한 사람 정답, 독립 취득 참조·압축 조건의 실제 보호 평가.
- 같은 버전 실제 녹화·발표 증빙. 자동 처리가 어려운 사례와 실패를 숨기지 않는다.

기존 `data/` 미커밋 5개 파일과 팀원 이력은 그대로 보존했다. 제출 10월 23일·발표 10월 30일, 실제 기기와 서버는 다음 날 진행하기로 한 사용자 결정을 유지한다.
