# 2026-10-20 이봉헌: 흐린 합성 결과의 생성 지문선 보완

## 요청과 변경

사용자가 처리본이 뿌옇고 지문선이 보이지 않는다고 보고했다.
앞선 처리 시간 문제도 함께 조사했다. V26의 합성 허용 변경만으로는
흐린 원본에서 낮게 측정된 재질 강도가 생성 무늬를 약하게 만드는 문제를 해결하지 못했다.

기능 커밋 `43b77c3`:

- 예방적으로 합성하는 영역에만 독립 생성 재질 강도 하한을 적용했다.
- V19 기본·관측 통과 영역·사람 검토 출력은 유지했다.
- 의미 분할·자세 작업과 Torch 시작을 겹치고 실패/시간 초과 시 소유 작업을 회수했다.
- COLFISPOOF CPU/CUDA를 명시적으로 고르는 비공개 실행 설정을 추가했다.
  기본은 CPU이며 CUDA는 TF32를 끄고, 실패 시 다른 장치로 자동 대체하지 않는다.
- 모델 가중치·학습 소스/해시 검사·검출/경계 임계값·HTTP 계약은 유지했다.

## 처리 시간과 채택하지 않은 실험

- 이전 CPU 단독 계측: `run` 118.98초, import 포함 128.15초.
  영역 준비 약 87.69초, 합성 약 18.18초. 내부 함수 시간은 중첩되므로 더하지 않았다.
- 별도 CPU 기준 프로세스 156.30초는 단위 검사와 겹쳐 엄밀한 속도 비교에서 제외했다.
- 이번 제공 사진 CUDA FP32 실행: 초기화·출력 저장 포함 **136.56초**,
  응답 처리 시간 **122,935ms**. 무거운 회귀와 동시 실행하지 않았다.
- 기존 대조 사진은 회귀와 겹쳤으므로 실행 시간을 성능 비교에 쓰지 않는다.
- TensorFlow 그래프의 매 요청 초기화와 4608 내부 입력의 4방향 처리가 남아 있다.
  상주 추론·초기화 캐시는 구현하지 않았으며, 120초 목표 달성으로 보고하지 않는다.
- 초기 TF32 허용 GPU 시험은 CPU와 마스크가 달라 채택하지 않았다.
  TF32를 끈 현재 GPU 경로는 제공 사진과 대조 사진의 위 화소 비교를 통과했다.
- 첫 작업 회수 통합 검사는 Windows venv의 하위 Python 때문에 정체되어 중단했다.
  소유 프로세스 트리를 종료하도록 수정한 뒤 전체 86개를 다시 실행했다.
