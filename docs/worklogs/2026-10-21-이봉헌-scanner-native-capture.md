# 실제 BioMini 원본 취득과 서버 비교 — 2026-10-21

## 확인한 실패와 수정

USB는 정상이고 센서 API도 HTTP 200이었으나 FFV `Enroll(20000)`이 `ScannerTimeout`을 반환했다. 공식 C# 샘플과 같이 SDK 초기화를 STA UI 스레드로 옮긴 뒤 실제 `TemplateCreated`와 비트맵 반환을 확인했다. 하지만 비교 앱의 영상 검증은 실패했다.

투명 팔레트 정규화를 추가해 확인했으나 실제 SDK 반환은 **150×200·Format24bppRgb 컬러 비트맵**이었다. 회색조 원본 계약에 맞지 않아 이를 거절한 것이며 컬러·투명 입력 검사를 완화하지 않았다. 등록 결과 영상을 회색조로 바꿔 센서 원본으로 설명하지 않는다.

이 PC의 10월 16일 SensorPreview 도구에서 확인했던 직접 UFS 콜백 어댑터를 원클릭 helper에 연결했다. `UFS_StartCapturing`은 원시 300×400·500ppi 회색조 샘플을 반환한다. 빈 균일 프레임을 제외하고 연속 3개의 `FingerOn` 프레임 후 최신 영상을 고른다. 밝기·해상도·생체 감지 설정을 바꾸지 않는다. FFV DB·등록·특징 추출을 취득 조건으로 쓰지 않는다.

helper가 캡처를 중단하고 이전 timeout을 복원하며 SDK 종료를 확인한 후 같은 사용자 전용 pipe로 PNG를 전달한다. 프레임은 메모리에만 두고 내보내기 전에는 이미지 파일로 저장하지 않는다. SDK 바이너리는 공개 Git·전달 ZIP에 넣지 않았다.

## 실제 장치·서버 확인

- 실제 연결 장치 1개. `UFS_Init`·장치 수/핸들·캡처 시작·종료·timeout 복원·`UFS_Uninit` 모두 SDK 코드 0.
- 직접 취득한 콜백 원본은 **300×400·500ppi**, 성공 시도에서 47개 프레임 중 3개가 `FingerOn`이었다. 회색조 PNG가 비교 화면에 들어왔다.
- 같은 학교 HTTPS 서버가 원본을 처리했고 Windows 앱이 요청 ID·입출력 해시·픽셀·반환 크기·변경 수·점수 메타데이터를 검증한 뒤 표시했다. 서버 설정이나 Android 코드는 이번 수정에서 변경하지 않았다.
- 사용자가 제공한 실제 결과 화면: SourceAFIS **3.18.1**, 원시 점수 **81.96**, 원본 특징점 **27**, 처리본 특징점 **57**, 변경 **48,991** 픽셀, 서버 처리 **1,891ms**.
- **0.2.4 원클릭 버튼으로 3회 모두 자동 비교까지 성공**했다고 사용자가 확인했다. 반복별 세부 수치·전체 지연 시간을 별도로 수집하지는 않았다.

1,891ms는 서버 처리 시간이며 센서 접촉·취득·전송·표시 전체 시간은 아니다. 81.96은 백분율이나 신원 확률이 아니다. 원본과 처리본의 직접 비교로, 독립 참조에 대한 보호 효과나 일반 성공률을 입증하지 않는다. 원본 지문·화면 이미지·개인 경로는 공개 기록에 넣지 않았다.

## 코드·배포 검사

- Windows **30/30 통과**. 기존 프로토콜·실제 프로세스/pipe·취소·점수·저장 검사와 SDK bitmap 호환, 투명 입력 거절 유지, 원본 콜백의 접촉/빈 프레임 선택, 정확한 샘플 보존을 포함한다. 이 자동 검사는 합성 계약 검사이며 실제 장치 확인과 구분한다.
- 0.2.4 자체 포함 Windows x64 EXE 게시. 직접 취득 코드 `8753f17`.
- 바탕화면 `BlurFing_센서원본취득_20261021` 전달본과 `BlurFing 센서 (최신)` 바로가기. 기존 설정은 백업 후 새 직접 취득 helper 경로로 수정했다.
- 기존 5개 data 파일의 미커밋 변경은 해시 대조로 보존하고 커밋하지 않았다. 모델·SDK·비밀 설정·지문 자료는 공개 Git에 포함하지 않았다.
