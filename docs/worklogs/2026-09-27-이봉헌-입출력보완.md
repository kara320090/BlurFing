## 보호 사본 저장 — BF-06

MediaStore가 저장 항목을 공개하지 못해 `update()`가 0을 반환해도 기존 코드는 성공으로 처리했다. 항목 생성 예외는 `Result` 바깥으로 빠졌고, 미완성 항목 삭제 중 예외가 나면 처음 발생한 오류를 덮었다.

- PNG/JPEG만 허용해 인코딩 형식과 파일 확장자·MIME이 일치하도록 했다.
- 항목 생성부터 파일 쓰기·공개까지 같은 오류 처리 범위에 둔다. 공개된 항목이 정확히 하나일 때만 성공으로 처리한다.
- 실패·취소 시 이번 호출이 생성한 항목만 정리한다. 삭제도 실패하면 최초 오류에 부가 오류로 남긴다.
- 코루틴 취소는 정리 후 다시 전달한다. 파일 쓰기 후 공개 직전에 취소 여부를 확인한다.

### 검증

합성 비트맵과 제어 가능한 ContentProvider를 사용한 `ImageSaverTest` 10개가 통과했다. PNG/JPEG 저장, 공개 실패, 생성 실패, 반환 URI 누락, 정리 실패, 취소 전달, 형식 불일치, Android 9 이전 저장 열 호환성을 확인했다. Android 10 동작은 Robolectric SDK 29, 이전 저장 열은 SDK 28에서 실행했다.

첫 회귀 테스트 실행에서 10개 중 5개가 실패했다. 이후 Robolectric의 파일 스트림 대체 동작 및 코루틴 예외 복사 영향을 제거하도록 테스트를 보정하고, 실제 저장 코드 수정 후 10개 모두 통과했다.

```powershell
./gradlew.bat testDebugUnitTest --tests com.blurfing.app.ImageSaverTest --max-workers=4 --console=plain
```

이 검증은 실제 스마트폰의 갤러리·저장 권한 시험이 아니다. 이미 공개가 끝난 사본을 취소 시 삭제하는 기능도 아니다. 실기기 저장·Android 8/9 권한 흐름·공간 부족 시험은 남아 있다.

## 사진 입력 검사 — BF-01·02

기존 사진 선택은 해상도 제한 없이 비트맵부터 디코딩했다. 오류 메시지에는 파일 제공자의 예외 문자열이 포함되어 내부 경로가 표시될 수 있었다.

- `SelectedImageLoader`에서 한 번 연 파일의 데이터만 사용한다. 최대 15MiB를 읽고, 픽셀 할당 전에 20,000,000픽셀 이하인지 검사한다. 픽셀 수 곱셈은 Long으로 계산해 정수 오버플로를 피한다.
- 같은 바이트에서 픽셀과 EXIF를 읽고 방향을 반영한다. 이미지 해상도를 임의로 낮추지 않으며 원본 파일을 수정하지 않는다.
- 용량·해상도 초과와 손상 이미지는 다시 선택할 수 있는 안내로 처리한다. 제공자의 내부 경로는 화면에 표시하지 않는다.
- 사진 선택 화면에 입력 제한을 안내한다. 서버 전송용으로 다시 인코딩된 PNG의 용량 검사는 기존 API 구현을 유지한다.

`SelectedImageLoaderTest` 10개가 통과했다. 정상 PNG와 원본 파일 보존, JPEG EXIF 90도 회전, 과대 PNG 헤더, 15MiB 초과 및 정확한 경계값, 픽셀 수 정수 오버플로, 손상 파일, 파일 경로 비노출, 오류 후 재선택, 선택 취소를 검증했다. 과대 해상도 시험은 합성 PNG 헤더를 이용해 큰 비트맵을 실제로 만들지 않았다.
