# 2026-10-20 실제 시연 인수 준비

사용자가 승인한 인수·시연 계획을 구현했다. 작업 기준은 최신 원격 `6e1a57b`이며, 팀원의 기존 자동 V23·Android 연결·최적화 구현은 보존했다. 아래 검사는 그 코드에 이번 변경을 더한 작업본에서 실행했다.

## 구현

- `demo/runtime.py`: 비공개 자산·고정 모델/인수 해시·기존 사용 자료 이력 검사, 환경별 패키지/`pip check` 기록과 실제 V6 validator probe, Ubuntu/Windows의 기존 사진·센서 API loopback 실행. 파일 검사와 모델 로드는 추론·기기·보호 승인이 아니다.
- `demo/connect.py`: 기존 SSH 인증을 사용하는 8001/8002 포트 전달과 실물 USB Android reverse. 기존 포트/매핑을 덮어쓰지 않고 자신의 연결만 정리한다. 양쪽 `/ready` 계약을 구분한다.
- `demo/rehearse_photo.py`: 실제 HTTP 3회 시도·실패 기록, 기존 V2 픽셀/마스크 검증, 반환 PNG 저장·재읽기, 새 private 증빙 폴더. 이 검증을 Android end-to-end로 표시하지 않는다.
- `demo/evaluate_photo.py`: 개발/평가의 사람·촬영 그룹·파일/RGB 중복과 기존 자료 재사용 검사. 미검출을 포함한 사람 정답에 후보/적용 마스크를 각각 비교한다. 거절 이유는 가시성 정답이 아니다.
- `demo/evaluate_scanner.py`: 별도 취득 참조에 원본/처리본을 동일 설정으로 실제 SourceAFIS 비교. 원시 점수·특징점·실패를 기록하고 보호 판정이나 새 임계값을 만들지 않는다.
- Android: 자동 입력 불러오기 또는 수동 재실행 시작부터 결과 검증·저장 재읽기 시간을 단조 시계로 표시한다. 저장 위치 선택/대기 시간을 포함한다. 요청별로 결합하고 복원 시 과거 시간을 재사용하지 않는다. 빌드에 `-PblurfingRevision=<commit>`을 지정해 화면에서 버전을 확인한다.
- 센서 내보내기: 기존 private comparison.json에 입력 출처를 남겨 FFV 새 취득과 파일 입력을 구분한다.
- 과거 문서의 V23 미연결 설명은 당시 기록임을 표시하고, 최신 자동 경로와 PC 사람 검토 경로를 구분했다. 제출 10/23·발표 10/30의 현재 절차는 [시연 안내](../../demo/README.md)를 따른다.

GitHub에 새 Linux 합성 회귀 workflow를 추가했으며 실제 실행 상태는 푸시 이후 확인한다. 합성 CI는 최신 V23 실제 Linux 모델 동등성을 대신하지 않는다.

## 미완료·외부 선행 조건

2026-10-20 원격 main·브랜치·Git LFS·릴리스를 확인했다. 실제 V6 가중치/대응 설정/사용 자료 레지스트리와 외부 모델은 공개 저장소에 없고 현재 작업 환경에도 인수되지 않았다. 인수 검사는 누락을 실패로 표시하며 임의 자산·빈 레지스트리·Mock으로 대체하지 않는다.

따라서 **실제 AI 재현·학습 개선·새 촬영 독립 평가·실제 매칭·120초 달성은 이번에 완료하지 않았다.** 자료 부족의 원인을 코드만으로 해결했다고 주장하지 않는다. 비공개 인수 자산과 기준 개발 입력을 받아 최초 실패 단계부터 재현하는 것이 다음 선행 작업이다.

실물 휴대폰·BioMini Slim 2·학교 Ubuntu는 사용자가 10/21~22일 사용할 수 있다고 답했다. 실제 학교 서버 접속은 내일 진행하기로 한 요청을 유지하여 이번에는 접속·설정 변경하지 않았다. 실제 FFV→서버→점수와 실물 Android의 3회 실행, Windows/Ubuntu 실제 모델/마스크 동등성, 독립 참조·압축 후 보호 평가, 실제 녹화·발표 증빙은 남아 있다.

기존 미커밋 `data/` 파일 5개의 바이트를 보존하고 커밋에 포함하지 않았다. 팀원 이력·작성자를 유지하며 강제 푸시나 날짜 조작을 하지 않는다. 모델·사진·실제 원본 해시·SDK·개인 설정·예산 문서는 커밋하지 않는다.
