# 2026-09-28 이봉헌 — 센서 SDK 조사·준비 소스 인수인계

관련 요구사항: BF-08, BF-11, BF-12. 담당 범위: Android 담당의 시스템 통합 준비 및 센서 담당 최승빈에게 전달할 자료 정리. 사용자 요청에 따라 Codex가 기존 자료 조사·소스 이관·빌드 스크립트 보완·컴파일 확인·Git 작업을 수행했다. 최승빈의 실장비 측정 업무를 완료한 것으로 기록하지 않는다.

## 변경 내용

- [인수인계 문서](../sensor-handoff.md)에 GitHub 센서 코드, Xperix 답변, 공식 다운로드, 무료 FFV의 기능 범위, 해외 배포 파일 검사 기록, 설치 절차와 담당별 후속 작업을 정리했다.
- BioMini Slim 2가 공식 FFV 지원 목록에 있다는 근거와 실제 장치 시험이 아직 남아 있다는 상태를 함께 표시했다. 11번가 제품이 잠겨 있거나 FFV와 비호환이라고 확인한 사실은 없다.
- 기존 로컬 `BlurFingFfvCapture.cs`를 [sensor/ffv-extension](../../sensor/ffv-extension/README.md)에 옮겼다. 공식 FFV C# 샘플에 BMP/PNG 저장 버튼을 추가하는 실험용 확장이다. C# 소스 내용과 저작권 표시는 그대로 유지했다.
- 빌드 스크립트에 `-SdkRoot` 인수와 필수 파일 검사를 추가해 SDK를 저장소 밖에 둔 팀원도 빌드할 수 있게 했다.
- 센서 취득·보호 전후 비교용 CSV 헤더와 [팀원 전달 메시지](../sensor-handoff-message.txt)를 추가했다. 실제 측정값이나 확정된 API 계약은 아니다.
- README·BF-08 상태를 연결하고, `.gitignore`에 FFV SDK 폴더·ZIP·실행파일·로컬 DB 제외 규칙을 추가했다.

## 이번에 수행한 검증

| 확인 | 결과 |
|---|---|
| FFV 확장 x64 컴파일 | 저장소의 `build-capture.ps1 -SdkRoot <로컬 공식 FFV SDK 경로>` 실행 성공. EXE 및 .NET Framework 4.8 설정 파일 생성 |
| 잘못된 SDK 경로 | SDK 파일이 없는 경로를 지정했을 때 `CSharpSample.exe` 누락을 설명하고 빌드 중단 |
| SDK·실행파일·DB 제외 규칙 | `git check-ignore`로 SDK 폴더의 DLL, SDK ZIP, 생성 EXE, `fingerprints.dat` 제외 확인 |
| 문서·공유 파일 | 상대 Markdown 링크 31개 유효, 기존 C# 소스 SHA-256 일치, 두 CSV가 중복 열 없는 헤더만 포함함을 확인 |

컴파일은 이전에 공식 FFV 배포본에서 확보한 참조 파일을 사용했다. 로컬의 기존 전체 ZIP은 다운로드가 중단된 상태이므로, 새 PC에서는 공식 전체 패키지를 다시 받아야 한다. 컴파일 성공은 SDK 전체 설치·실장비 호환성 확인을 대신하지 않는다.

이전에 기록한 UFS 합성·오류 검사 16개와 FFV 모듈 선택 화면 확인은 과거 검증이다. 이번 커밋에서는 센서 앱·SDK 설치파일을 실행하지 않았고, Android·백엔드·UFS 앱 테스트도 변경 범위가 아니어서 재실행하지 않았다.

## 후속 작업

최승빈이 제품·드라이버·SDK 버전을 확인하고 실물 USB 연결, 공식 샘플 취득, BMP/PNG 저장, 반복 취득·실패·재연결을 검증한다. 유재윤과 사진 원본의 비교 가능성과 평가 엔진을 정하고 보호 전후 평가에 연결한다. FFV는 이미지 파일 입력을 지원하지 않으므로 그 평가 전체를 FFV로 구현한다고 가정하지 않는다.

실제 지문·등록 DB·SDK 바이너리·안전성이 확정되지 않은 해외 설치파일은 이 변경에 포함하지 않는다. 개인정보와 원본 실험 자료는 동의 범위에 맞는 별도 저장 위치에서 관리한다.
