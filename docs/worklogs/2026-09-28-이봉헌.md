## 확인한 문제와 변경

앱은 Android 8(API 26)부터 지원하며 manifest에 `WRITE_EXTERNAL_STORAGE`가 선언되어 있었지만, 저장 버튼에서 실행 중 권한을 요청하는 코드가 없었다. Android 8·9에서 권한이 없는 경우 파일 저장만 재시도해도 해결되지 않았다.

- 저장 버튼에서 OS 버전과 현재 권한을 검사한다. Android 8·9에서 필요할 때만 UI에 요청 식별자를 반환하고, `RequestPermission` 계약으로 시스템 권한 창을 연다.
- 목적 설명이 필요한 경우 사본 저장 목적과 계속·취소 선택을 표시한다. 권한 확인 중에는 저장 버튼을 비활성화하고 상태를 안내한다.
- 허용 결과와 실제 권한을 다시 확인한 뒤, 권한 요청 당시의 사본을 한 번 저장한다. 중복 응답은 무시한다.
- 거부·취소해도 원본·처리본·수정 영역과 비교 화면을 유지한다. 다시 시도하거나 앱 설정에서 권한을 허용하도록 안내한다.
- 사진 교체·편집 복귀·새 처리·초기화는 기존 권한 요청을 무효화한다. 새 요청을 대기하는 동안 이전 요청의 응답이 와도 새 저장을 시작하지 않는다.
- Android 10(API 29) 이상에서 앱 소유 미디어를 저장할 때는 기존 저장 권한 요청을 생략한다.

UI는 실행한 권한 요청 ID를 `rememberSaveable`로 보존한다. ViewModel은 현재 비교 상태의 요청 ID와 일치하는 응답만 적용한다. 프로세스가 종료되어 사진 상태를 잃으면 이전 응답을 사용해 저장하지 않는다.

## 기기에서 남은 확인

1. Android 8·9에서 앱 권한을 초기화하고 합성 사진을 처리한 뒤, 저장 버튼으로 시스템 권한 창이 열리는지 확인한다.
2. 허용 시 갤러리에 사본 하나가 생기고, 거부·목적 설명 취소 시 비교 화면이 유지되는지 확인한다.
3. 권한 요청 중 화면 회전·Activity 재생성 후 응답이 한 번만 처리되는지 확인한다.
4. 다시 묻지 않도록 거부한 경우 오류 안내에 따라 앱 설정에서 권한을 허용하고 재시도한다.
5. Android 10 이상에서 기존 저장 권한 창 없이 사본이 생성되는지 확인한다.

실제 스마트폰·에뮬레이터 UI, 시스템 권한 창·갤러리, 팀 서버 통신, AI 보호 성능, 센서 취득은 이번 검증에 포함하지 않았다.
