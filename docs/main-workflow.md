# main 작업 및 팀장 검토 절차

모든 개발은 기본적으로 main에서 진행한다. 각 팀원은 자기 작업을 직접 커밋·push하고, 이봉헌은 팀원 변경을 검토하면서 Android 앱과 시스템 통합 개발을 병행한다. 팀원 작업을 모두 모아 팀장 이름으로 다시 커밋하지 않는다.

## 작업을 시작할 때
1. `git status --short --branch`로 브랜치와 미커밋 작업을 확인한다. main이 아니면 기존 작업 상태를 확인한 후 안전하게 전환한다.
2. `git fetch origin` 후 `git log --oneline HEAD..origin/main`과 `git diff --stat HEAD...origin/main`으로 새 원격 커밋과 변경 파일을 확인한다.
3. 작업 트리가 깨끗하고 로컬 전용 커밋이 없으면 `git pull --ff-only origin main`으로 반영한다. 로컬 미커밋 작업이 있으면 먼저 해당 작업을 보존·정리한다. 자동으로 덮어쓰거나 stash하지 않는다.
4. 팀원 변경 중 앱에 영향을 주는 API·좌표·결과 형식·실행 방법을 우선 검토한다. 모든 팀원 작업이 끝날 때까지 기다리지 않고 독립적인 본인 작업을 진행한다.

## 이봉헌의 작업 구성
| 구분 | 실제 수행할 일 | 남길 근거 |
|---|---|---|
| 팀원 변경 검토 | 관련 커밋 읽기, 실행·오류 재현, 앱 영향 확인 | 검토한 커밋 SHA, 파일, 확인 결과, 남은 질문 |
| 본인 앱 개발 | 입력·영역 표시·상태·통신·저장 구현 | 기능 커밋, 요구사항 ID, 실제 검증 결과 |
| 시스템 통합 | API·AI·영역·센서 결과 연결, 좌표·상태·오류 수정 | 연동·오류 수정 커밋, 재현 절차와 전후 결과 |
| 진행 관리 | 의존 작업·기한·장애 요인 정리 | Issue와 구체적인 후속 조치 |

검토 결과 변경이 필요하지 않다면 검토 기록만 남긴다. 검토 기록에는 실제 확인한 내용을 적고, 의미 없는 문서 변경을 만들어 커밋 수를 늘리지 않는다. 외부 메시지 전송은 별도 요청이 있을 때만 수행한다.

## 커밋과 push
작업 중에는 화면, 통신, 좌표 변환, 저장, 검증처럼 의미 있는 단위가 완료될 때 커밋한다. 작업한 날에는 확인된 변경을 원격에 공유해 진행 이력이 보이도록 한다. 하루 커밋 수를 고정하거나 이미 완료한 작업을 날짜별로 나누어 올리지 않는다.

1. `git diff`로 변경을 검토하고 관련 검증을 실행한다.
2. `git add <본인이 확인한 파일>`로 필요한 파일만 선택한다. 다른 에이전트나 팀원의 미커밋 파일을 섞지 않는다.
3. `git diff --cached`를 확인하고 문제와 결과를 설명하는 메시지로 커밋한다.
4. `git fetch origin` 후 `git rev-list --left-right --count HEAD...origin/main`으로 상태를 확인한다. 왼쪽은 로컬에만, 오른쪽은 원격에만 있는 커밋 수다.
5. 오른쪽이 0이면 `git push origin main`을 실행한다. 양쪽에 커밋이 있으면 아래 절차로 합친다. 왼쪽이 0이고 원격만 앞서면 깨끗한 작업 트리에서 fast-forward로 동기화한다.

## 동시에 push해서 이력이 갈라졌을 때
새 원격 변경의 내용을 확인하고, 작업 트리가 깨끗한 상태에서 `git merge --no-edit origin/main`으로 양쪽 커밋을 보존해 합친다. 충돌이 발생하면 파일별 변경 의도를 확인해 해결하고 관련 테스트를 다시 실행한다. API 의미나 팀원 의도가 불명확하면 해당 충돌의 해결은 보류하고 확인이 필요한 내용을 기록한다. 한쪽 파일을 통째로 선택하거나 강제 push로 덮어쓰지 않는다.

merge가 완료되어도 검증 전에는 push하지 않는다. push가 다른 팀원의 새 커밋으로 다시 거절되면 fetch·검토·merge·검증을 반복한다. 이미 공유한 커밋의 작성자·날짜·내용을 바꾸거나 rebase하지 않는다. 같은 파일을 동시에 바꾸는 일이 반복되면 담당 범위와 수정 순서를 먼저 맞춘다.

## 실제 작업 기록 양식
필요한 날 `docs/worklogs/YYYY-MM-DD-담당자.md`에 아래 항목을 기록한다. 반복적인 파일을 미리 생성하지 않는다.

- 실제 작업 날짜와 담당자
- 관련 요구사항·Issue
- 검토한 팀원 커밋 SHA와 구체적인 확인 결과
- 직접 구현·수정한 내용과 본인 커밋 SHA
- 실행한 검증 명령·환경·결과
- 실행하지 못한 검증과 이유
- 남은 의존 작업과 다음 조치

## 안티그래비티에 매번 전달할 지시
현재 main과 작업 트리 상태를 확인하고 origin/main의 새 커밋을 검토해. 팀원 변경 중 앱·API·영역 좌표·평가 결과에 영향을 주는 부분을 확인하면서 이봉헌 담당 Android·통합 작업을 이어서 진행해. 실제로 완료한 단위마다 검증하고 커밋·push해. 팀원 커밋과 내 수정의 작성자를 유지하고 검토·구현·검증을 구분해 기록해. 같은 작업 폴더를 다른 에이전트가 수정 중이면 동시 편집하지 마. 강제 push와 자동 브랜치·PR 생성은 하지 마.
