# Android 서버 연동 확인 절차

담당: 이봉헌 — Android 앱 및 시스템 통합

관련 요구사항: BF-05, BF-06, BF-07, BF-12

## 로컬 Mock 프리뷰

1. 사진을 선택하고 손끝 영역을 직접 확인·수정한다.
2. 보호 설정에서 기본값인 Mock 모드를 유지한다.
3. 강도를 선택하고 'Mock 프리뷰 만들기'를 누른다.
4. 비교 화면의 Mock 표시를 확인하고 사본을 저장한다.

초기 두 영역은 합성 후보다. 자동 탐지와 실제 지문 보호 성능은 아직 확인되지 않았다.

## 팀 백엔드 연결

2026-09-27 기준 `backend/main.py`에는 요청 이미지·영역 검증, AI 처리 모듈 연결 지점, 결과 PNG 형식·해상도 검증과 반환이 있다. AI 모듈이 연결되지 않은 현재 상태에서 영역이 있는 요청은 HTTP 503 / `PROCESSOR_UNAVAILABLE`을 반환한다. 영역을 생략하거나 빈 배열을 보내면 `no_regions`이며 자동 영역 추출은 아직 연결되지 않았다. 이미지 제한은 15 MiB 및 20,000,000픽셀이다.

1. 백엔드·AI 담당자가 `app.state.protection_processor`에 실제 처리 함수를 연결한다. 함수는 `(image_bytes, method, strength, regions)`를 받아 입력과 같은 크기의 PNG 바이트를 반환한다. 연결 전에는 아래 오류 안내와 Mock 전환을 확인한다.
2. Android 보호 설정 화면에서 '백엔드 서버에서 처리'를 선택한다.
3. 에뮬레이터에서 같은 PC의 서버를 사용할 때는 `http://10.0.2.2:8000`을 입력한다.
4. USB 기기를 사용할 때는 Android SDK의 `adb reverse tcp:8000 tcp:8000` 실행 후 `http://127.0.0.1:8000`을 사용한다.
5. HTTPS 서버라면 해당 주소를 입력한다. 개발 빌드는 위 로컬 주소와 localhost에 한해 HTTP를 지원하고, 배포 빌드는 HTTPS를 사용한다.
6. 합성 사진으로 '서버로 전송 및 처리'를 누른다. 사진은 입력한 서버로 전송된다.
7. 서버가 반환한 이미지가 비교 화면에 나타나는지 확인하고 별도 사본으로 저장한다.

서버 설정은 해당 보호 설정 화면에 머무르는 동안 유지한다. 앱을 재시작하거나 설정 화면을 새로 열면 기본 Mock 모드를 사용한다. TLS 인증서 검증을 끄지 않으며 다른 주소로의 자동 리다이렉트도 허용하지 않는다.

현재 서버의 HTTP 503에는 '보호 처리 서비스를 일시적으로 사용할 수 없습니다'라는 안내가 표시된다. 사진과 수정 영역이 남아 있으므로 '백엔드 서버에서 처리'를 해제하고 로컬 Mock 프리뷰로 계속 확인할 수 있다. 이전 서버의 HTTP 501에는 기능 미준비 안내, HTTP 415에는 PNG/JPEG 형식 안내가 표시된다. 오류를 처리 성공으로 표시하거나 서버 내부 응답을 그대로 노출하지 않는다.

## 서버가 제공할 성공 응답

- 요청과 동일한 `request_id`, `status: succeeded`, `result_kind: real`.
- EXIF 방향이 정규화된 입력과 같은 폭·높이의 완성 이미지.
- `image_base64`: PNG 또는 JPEG의 표준 Base64 문자열. data URL 접두사는 사용하지 않는다.
- `mime_type`: 실제 이미지 형식과 일치하는 `image/png` 또는 `image/jpeg`.
- `applied_regions`: 실제 처리한 영역. 지문 미검출은 `status: no_regions`로 구분한다.

없는 이미지, 다른 요청 ID, 손상된 Base64, 해상도·형식 불일치는 오류로 처리한다. `real` 응답에 대한 로컬 블러 대체나 원본 이미지 저장은 하지 않는다. 통신 실패 후에도 입력 사진과 수동 영역이 남으므로 같은 설정 화면에서 재시도한다. 처리 중 취소하거나 초기화한 뒤 도착한 응답은 화면에 적용하지 않는다.

## 검증 범위

자동화 테스트의 HTTP 서버는 MockWebServer이며 생체정보 없는 합성 응답만 사용한다. Robolectric 테스트는 Android 이미지 처리·ViewModel 상태를 확인한다. 이 결과를 실제 팀 보호 API, 스마트폰 UI, 지문 센서 또는 방어 성능의 실측으로 간주하지 않는다.

실제 기기에서는 사진 선택 → 영역 편집 → 서버 처리 → 비교 → MediaStore 저장을 추가 확인해야 한다. 서버 취소 후 서버 측 작업 중단·임시 파일 삭제도 백엔드와 별도로 검증한다.

참고: [Android 네트워크 보안 설정](https://developer.android.com/privacy-and-security/security-config), [Robolectric 설정](https://robolectric.org/getting-started/).
