# 보호 처리 API 초안

상태: 담당자 공동 검토 전 초안. 서버 구현과 확정된 계약을 의미하지 않는다.

## 공통 규칙
- API 버전은 `/v1`로 구분한다. 로컬 개발은 호스트·포트를 환경 설정으로 받는다.
- 앱은 EXIF 방향을 픽셀에 반영하고 방향 정보를 정규화한 사진을 보낸다. 영역 좌표는 이 정규화된 원본의 좌상단 기준이다.
- 영역은 `{x, y, width, height}`이며 모두 0~1의 상대값이다. `width`, `height`는 양수, `x + width <= 1`, `y + height <= 1`을 만족한다.
- 앱 화면의 여백·확대·축소를 포함한 좌표 변환은 이봉헌이 검증한다.
- `request_id`로 요청과 응답을 대응시키고, 취소되거나 교체된 요청의 늦은 응답은 화면에 적용하지 않는다.
- 입력 용량·해상도·시간 제한은 백엔드와 공동 결정하여 앱에도 반영한다.

## POST /v1/protect
요청 형식은 multipart/form-data를 후보로 한다.

| 필드 | 초안 |
|---|---|
| image | 정규화된 정지 사진 파일 |
| request_id | 요청 식별자 |
| method | 초기 지원 값 `gaussian_blur`; 연구 방법은 검증 후 추가 |
| strength | 0~1 사이 보호 강도, 구체적 커널 매핑은 구현 시 정의 |
| regions | 상대 좌표 배열을 JSON 문자열로 전달; 없으면 자동 후보 추출 |

성공 응답은 아래 JSON 예제와 함께 보호 PNG/JPEG 데이터를 반환하는 형태를 후보로 한다. 전송 형식(base64 또는 분리 다운로드)은 이미지 크기·메모리 측정 후 공동 확정한다. 예제의 `image_base64: null`은 계약 예시용 자리이며 실제 성공 응답의 완성 이미지가 아니다.

```json
{
  "request_id": "synthetic-example-001",
  "status": "succeeded",
  "result_kind": "mock",
  "image_base64": null,
  "mime_type": "image/png",
  "applied_regions": [{"x": 0.2, "y": 0.1, "width": 0.1, "height": 0.2}],
  "processing_ms": null,
  "warnings": ["MOCK_RESULT"]
}
```

영역이 없으면 `status: no_regions`와 확인 안내를 반환하고 보호 성공으로 표시하지 않는다. 지원하지 않는 방법, 잘못된 영역, 파일 크기 초과, 처리 오류를 구분한다. 오류 응답은 `request_id`, `code`, `message`, `retryable`을 포함하고 원본 이미지나 내부 경로를 메시지에 포함하지 않는다.

## 연구용 평가 결과
일반 사진 보호 응답에 가짜 매칭 점수를 넣지 않는다. 연구 도구의 측정 결과에는 비식별 sample ID, 참조 ID, 엔진·버전·설정, 원본 점수, 처리본 점수, 원본 유효성, 영상 품질, 처리 시간과 압축·축소 조건이 필요하다. 미측정 값은 null로 표시한다. 점수를 확률이나 0~100% 일치율로 바꾸지 않는다.

## 확정 전에 결정할 사항
요청 취소의 서버 동작, 다운로드 결과 수명, 최대 파일 크기·타임아웃, 미검출 응답, 평가 결과 경로를 담당자와 합의한다. 합의 후 기계 판독 가능한 OpenAPI와 계약 테스트를 추가한다.
